Каждое изменение начинается с части CORE, к которой оно относится, — здесь {audio}; в окне Welcome это точка цвета части. У каждой части своя версия: major — когда изменение ломает код или требует миграции, minor — для новой возможности, patch — для исправлений.

1.3.93 — 2026-11-02

В 1.3 появляется полная поддержка геймпада, по этапам: режимы ввода и определение устройства, навигация по UI слоями, группами и элементами, подсказки и иконки кнопок, виртуальный курсор, вибрация, читаемость на Steam Deck и локальный мультиплеер — поверх существующего InputSystem, API которого сохраняется. Этот раздел растёт с каждым этапом.

Ввод

  • {input} InputGamepadSettings — настройки поддержки геймпада: режимы и определение устройства, навигация, виртуальный курсор, вибрация, Steam Deck, иконки кнопок. Значения CORE по умолчанию — Resources/CoreInputDefaults; собственный ассет игры Resources/CoreInputSettings, созданный в Tools/CORE/Settings → Input, имеет приоритет. Пустые ссылки на actions берут карты UI и VirtualCursor ассета CORE по имени.
  • {input} InputHost — привязан в ProjectInstaller, после инициализации игры собирает сервисы геймпада в фиксированном порядке и тикает их по unscaled-времени через GlobalUpdater: IsInitialized, Initialized, Disposing, WhenInitialized, Settings, Input. Сервисы следующих этапов — его свойства.
  • {input} InputSystem.ResolveAction — InputActionReference, action ассета на диске или пара (map, action) превращаются в action runtime-копии с тем же id, поэтому переназначения и определение устройства видят один и тот же action; ассет на диске никогда не используется напрямую.
  • {input} InputMode, GamepadFamily, EventSystemPolicy и enum'ы навигации UIGroupNavigationMode, UIGroupSwitchPolicy, UINavigationDirection, UIGridScoringMode, UIInputPressTrigger.
  • {input} Режимы ввода и определение устройства: InputHost.Mode (InputModeService — CurrentMode, SetInputMode, InputModeChanged) и InputHost.Devices (InputDeviceService — ActiveDevice, CurrentGamepadFamily, Classify, ActiveDeviceChanged, GamepadFamilyChanged), плюс у хоста свои CurrentMode, CurrentDevice, CurrentGamepadFamily и события. Режим следует за последним реально использованным устройством: каждый сработавший action взвешивается по величине его контрола относительно порогов, а текущий геймпад, клавиатура и мышь опрашиваются каждый кадр — устройство засчитывается, даже если ни одна его карта не включена. Warp мыши, не-нативная мышь (виртуальный курсор) и мышь в окне InputHost.SuppressMouseDeviceUsed не засчитываются никогда. При удалении активного устройства фолбэк: текущий геймпад, любой геймпад, клавиатура, нативная мышь — в этом порядке.
  • {input} InputHost.CursorControl (CursorControlService): в режиме геймпада аппаратный курсор скрыт и заблокирован (режим блокировки и принудительное применение каждый кадр — из InputCursorSettings), в Keyboard&Mouse и при dispose возвращается прежнее состояние; IsCursorBlocked. CustomCursor по-прежнему меняет картинку курсора.
  • {input} InputHost.Icons (InputIconService): TryResolve(action | reference, family, out InputIconContent) — иконка и LocKey-подпись action для семейства геймпада из InputGamepadSettings.ActionIcons (запись Generic — фолбэк); GetBindingDisplay(action, bindingIndex) и GetControlDisplay(controlPath) — что биндинг показывает на экране управления, с учётом переназначений: читаемое имя контрола (латиницей при любой раскладке; composite склеивает части, W/S/A/D), иконка и подпись записи ControlIcons, если она есть, иначе спрайт клавиши CORE по KeyCode пути в размере InputGamepadSettings.KeyIconSize. InputLabel.Resolve(key) превращает ключ подписи в текст: ключ из таблиц даёт перевод, любой другой показывается как введён.
  • {input} UIInputStandaloneIcon (CORE/Input/UI Input Standalone Icon): Image, показывающий иконку action для активного семейства и следующий за каждой его сменой; Bind(action | reference | map, action), ClearBinding, Refresh. Для подсказок HUD и туториалов, независимо от навигации и режима ввода.
  • {input} InputSceneComponent — база компонентов сцены поддержки геймпада: InputHost приходит через DI (создающий контейнер, иначе DiContainerRef.Container в Awake, иначе более поздний Container.Inject), OnAttach / OnDetach сбалансированы при любом порядке инъекции и включения.
  • {input} InputHost.UI (UIInputService): EventSystem и его InputSystemUIInputModule от имени навигации. В режиме геймпада у модуля отбираются move/submit/cancel (у навигации CORE один владелец) и возвращаются в Keyboard&Mouse и при dispose; EventSystemPolicy.UseExisting (по умолчанию — EventSystem есть в ProjectContext) не добавляет и не удаляет модули, CreateIfMissing создаёт CoreInputEventSystem, когда в сцене его нет; за уничтоженным EventSystem следует EventSystem.current, работающий никогда не подменяется. SetSelected, ClearSelected, RestoreSelection (цель фокуса, иначе последнее выделение) — восстанавливается при входе в Gamepad с RestoreFocusForGamepad, очищается в Keyboard&Mouse с ClearFocusForKeyboardMouse.
  • {input} Контексты навигации — основа локального мультиплеера, живущая в ядре: InputHost.Contexts (UINavigationContextHost) держит UINavigationContext на игрока (Primary, ForPlayer(i), Available, AvailabilityChanged; у контекста IsAvailable, Mode, GamepadFamily, GamepadInputGate, AccentColor, ResolveAction, ModeChanged, GamepadFamilyChanged). UINavigationScope (CORE/Input/UI Navigation Scope) на корне панели направляет всё под ней к игроку (PlayerIndex, SetPlayerIndex, SetContext); Contexts.Resolve(component) отвечает primary без обхода иерархии, пока нет ни одного scope, Resolve(component, ref UINavigationScopeCache) кэширует по Version, InvalidateCaches после переноса поддерева; компоненты-IUINavigationContextListener узнают, когда маршрутизация могла измениться (панель, выключенная целиком, их не будит).
  • {input} InputHost.GamepadInputGate (GamepadInputActivationGate): после входа в режим геймпада ввод UI удерживается, пока стики, D-pad и navigate action не станут нейтральными (SuppressInputOnGamepadEnter; без navigate action — один repeat delay) — стик, открывший меню, по нему не ходит; IsInputAllowed, ArmSuppression.
  • {input} Навигация по UI геймпадом — компоненты (CORE/Input/…): UIInputLayer (экран или панель: запись в стеке навигации своего игрока; AutoActivate входит в стек при включении в режиме геймпада, AllowEmptyGroup, RememberLastFocus, DefaultGroup, Push / Remove / Rebuild / MarkDirty, BackRequested — слой никогда не закрывает окно сам), UIInputGroup (список, сетка или кольцо элементов: NavigationMode, GridScoring, SwitchPolicy со связями Left/Right/Up/DownGroup, DefaultElement, RememberLastElement, AllowExternalNavigation, ActivationAction / ExitAction, Activated / Deactivated), UIInputElement на Selectable (UIInputElementBase для наследования: Priority, IsNavigationEnabled, AllowInputSubmit, Selected / Deselected, IsFocused, SubmitFromCode; доступность = интерактивность Selectable, цепочка CanvasGroup, компоненты IUIInputElementAvailability рядом, IUIInputRestrictions игры). Элементы упорядочены по Priority, затем по месту в иерархии; явная навигация Unity у Selectable повторяет порядок CORE (UINavigationMap).
  • {input} InputHost.Navigation (IUINavigationService, у каждого игрока — UINavigationContext.Navigation): стек слоёв — верхний определяется по sorting order канваса и иерархии, а не по порядку push — ActiveLayer / ActiveGroup / ActiveElement, Move, Submit, Cancel (Back, изменивший стек, поглощается на кадр: LastBackConsumedFrame), Lock, ValidateFocus, MarkDirty (перестроения отложены и объединены, flush в LateUpdate перед проверкой фокуса), PresentFocus; события ActiveLayerChanged, ActiveGroupChanged, ActiveElementChanged, NavigationMapRebuilt, FocusLost, FocusRestored, BackRequested, LockChanged. Живёт только в режиме геймпада: в Keyboard&Mouse слои очищаются, при возврате включённые автоактивируемые возвращаются. Фокус primary — выделение EventSystem, возвращается на него каждый LateUpdate; фокус игрока идёт через select-обработчики.
  • {input} Ввод навигации: InputHost.NavigationInput (UINavigationInputProvider — navigate, submit и cancel из InputNavigationSettings, иначе из карты UI CORE: дедзона, гистерезис на диагоналях, повтор по RepeatDelay / RepeatRate, SuppressHeldDirection) и InputHost.GroupSelectionInput (UIGroupSelectionInputProvider — в слой, допускающий пустой фокус, входят по ActivationAction группы и выходят по её ExitAction). Оба работают только в режиме геймпада, за gate; карта actions включается через провайдеры CORE (InputSystem.RegisterProvider(mapName)), поэтому ограниченная группа по-прежнему её глушит.

Локализация

  • {localization} Локализация теперь собственная в CORE: CSV-таблицы (Key, Comment, en, ru, …) в папках записи ресурсов Localize, один столбец на язык, RFC 4180 с разделителем , ; или табуляцией, UTF-8 — экспорт из Excel и Google Sheets работает как есть. Текст откатывается к родительскому языку (pt-BR → pt), затем к запасному языку нового Resources/LanguageSettings; отсутствующий ключ логируется один раз и показывается как #Key#.   • {localization} Кодогенерация пишет LocKeys.<Table>.<Key> и реестр таблиц (LocalizationKeys.cg.cs). LocKey сериализуется самим ключом, а не числом: переименование или удаление другого ключа больше не сдвигает то, что показывает префаб. Сохранения

  • {core} Слот сохранения — папка файлов: основной SaveData_<Id>.json (счётчик id слота, LocationCustomData) и сколько угодно именованных дополнительных файлов SaveFileData (Location_3.json). Компонент с новым интерфейсом ISaveGameFileComponent указывает свой файл (SaveFile, пусто — основной), свой ключ в нём (SaveKey) и LoadPriority. SaveSystem.Save пишет основной файл и только файлы зарегистрированных компонентов — то, что загружено сейчас; остальные файлы слота не трогаются. SaveFiles(files, includeMain) сохраняет выбранные файлы, LoadFile(name) загружает один (OnFileLoadingComplete), SaveSystem.SlotFolder — откуда они читаются. При сохранении в другую папку (автосейв) незаписанные файлы слота переносятся туда же (SaveData.AdditionalFiles; другие файлы в папке не трогаются). SaveData.DeleteSave удаляет всю папку. Игра с одним файлом на слот работает как раньше.
  • {core} SaveSystem.Load сам раздаёт данные: каждый ISaveGameFileComponent получает LoadData в порядке LoadPriority (при равных — в порядке регистрации), затем вызываются ISaveGameReferences.ResolveReferences и ISaveGameCallbacks.OnAfterLoad; ISaveGameCallbacks.OnBeforeSave — перед сбором данных. Фиксированной задержки в 1 с перед OnLoadingComplete больше нет. Обычный ISaveGameBaseComponent по-прежнему берёт данные из OnLoadingComplete. Переданный в Load SaveData теперь становится данными Model.LocationData (вместе со счётчиком id), как и прочитанный с диска.
  • {core} SaveGameCollection<TComponent, TData> сохраняет все зарегистрированные сущности одного вида (здания, юниты, предметы) одним списком: каждая сущность сама собирает свой TData, при загрузке получает его по Id или создаётся фабрикой, а после всей загрузки восстанавливает ссылки по id в ResolveReferences. SaveGameComponentData теперь наследует SaveGameBaseComponentData. Пример — Examples/Scripts/SaveSlotFilesExample.cs (консольная команда example.save_slot_files).
  • {core} Каждый файл слота — основной, дополнительный, автосейв — пишется атомарно: в <file>.tmp, который затем заменяет файл; раньше старый файл сначала удалялся. SaveFileIO.UseThreadPool = true переносит сериализацию, запись и чтение в пул потоков для больших сохранений (по умолчанию и на WebGL выключено: данные сохранения не должны обращаться к Unity API), SaveFileIO.Formatting делает их компактными. Исключение сохраняет причину, а не превращается в "Invalid string length", упавшее сохранение больше не оставляет игру на паузе, а сохранение не снимает паузу, которая стояла до него.
  • {core} Миграции сохранений: файл хранит FormatVersion; SaveMigrations.Register(toVersion, (json, fileName) => …) мигрирует старые файлы на сыром json до чтения. У данных компонента есть DataVersion: переопределите CurrentDataVersion и Migrate(fromVersion); элементы коллекции мигрируют тоже.
  • {core} Файлы слота пишутся с TypeNameHandling.Auto ($type только там, где объявленный тип отличается) и биндером SaveTypes: SaveTypes.Register<T>(alias, legacyNames) пишет тип под алиасом и читает его по старым именам, так что переименование или перенос класса не ломает сохранения. Файлы с $type везде по-прежнему читаются.
  • {core} SaveSystem.SaveAuto ротирует слоты автосейва GlobalConfig.MaxAutoSaveSlots (свободный, иначе самый старый; 0 выключает автосейв) — раньше настройка нигде не читалась.
