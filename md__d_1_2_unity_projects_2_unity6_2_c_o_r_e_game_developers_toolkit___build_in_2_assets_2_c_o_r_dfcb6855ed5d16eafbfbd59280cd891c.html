CORE Editor Kit (<tt>CORE.EditorKit</tt>, asmdef <tt>EditorKit_AD</tt>)

Source: Assets/COREToolkit/EditorKit/. The UI Toolkit base every CORE editor window — and every window of a plugin built on CORE — is made from. Open Tools → CORE → Editor Kit Gallery to see each component live; Gallery/KitGalleryWindow.cs is the reference use of all of them.

Facts that shape how you use it:

  • Portable. The assembly references nothing but Unity and Newtonsoft Json. Your editor assembly references EditorKit_AD (by name); never the other way round. It compiles on Unity 2022.3 and Unity 6.
  • Editor only, no DI. Windows are created by Unity (GetWindow<T>()), components with new. The runtime "instantiate through the container" rule does not apply here.
  • Logging: the kit uses its internal KitLog (prefix [EditorKit]) because it cannot see DebugHelper. Code using the kit from a CORE assembly still logs through DebugHelper.

Module identity

CORE's own is CoreEditorModule (Scripts/Editor/Game/Module, id core, prefix Game_, ToolkitVersion). KitModule (abstract): Id (prefix of keys and glyphs), Title (translated), AssemblyPrefix, Description, Version, Accent, Glyph, Order, RootFolder, Parts (KitModulePart: Id, Title, Color, Version, Glyph, Description, Features (one per line, the tile's tooltip), ManualPage (a click on the tile opens it) — the parts of a package with versions of their own; FindPart(id)). Static All, AllOf<T>() (one family), Find(id), Of(Type), Of(Assembly) (longest prefix wins); CreateBadge(). Exactly one per package, in its editor assembly, found by TypeCache — nothing is registered by hand.

Contributions and the ready-made window frames

A package contributes to shared windows by deriving a KitContribution in its editor assembly — found by KitContributions.All<T>() (TypeCache, sorted by module order then Order then Id), owned by the KitModule of its assembly, never registered by hand. Every frame below adds COREEditorKitFrames.uss (KitWindowFrames.Apply) and shows a KitEmptyState when nothing contributes. CORE hosts everyone's contributions; a plugin's own window overrides Includes(...) to show only its family.

Theme

  • COREEditorKit.uss (EditorKit/Theme), found by name. KitTheme.Apply(root) adds it with kit-root and kit--dark/kit--light. Variables: --kit-bg, --kit-surface, --kit-surface-2, --kit-surface-3, --kit-border, --kit-border-soft, --kit-text, --kit-text-muted, --kit-text-faint, --kit-accent (+-hover, -soft), --kit-on-accent, --kit-success|warning|error|info (+-soft), --kit-shadow.
  • A window's own sheet: KitTheme.AddSheet(rootVisualElement, "<FileName>") (cached); it uses only the variables above; classes are BEM (block__element--modifier). KitTheme.ApplyMono(element) for code/json.
  • KitTone: Neutral, Accent, Info, Success, Warning, Error. KitTheme.SetTone(element, block, tone) toggles block--tone classes. KitPalette: Accent, Neutral, tone colors, Of(tone), WithAlpha, Hex(0xRRGGBB). Module colors are not in the palette — they are each KitModule.Accent.

KitGlyphs.Of(tone), Has(name), Find(name).

A package adds its own: KitGlyphs.Register("<module>.<name>", "M4 18 H20; R 6 8 12 6 2") from an [InitializeOnLoadMethod]. Grammar (24×24 grid, absolute): parts split by ;, * prefix = filled; M x y, L x y, H x, V y, C x1 y1 x2 y2 x y, Q x1 y1 x y, Z, O cx cy r (circle), R x y w h r (rounded rect). Stroke 1.8 units, round caps. Check it on the Gallery's Glyphs page.

Texts

  • KitText.Tr(key), Tr(key, params object[] args) — chosen language → English → [key] (recorded in MissingKeys; the Gallery's Feedback page lists them). using static CORE.EditorKit.KitText; in windows.
  • Language (EditorPrefs EditorKit.Language, shared by every kit window of every package), Languages, LanguageName(code) (the table's language.name), ShowKeys, Has(key), Reload(), event Changed.
  • Tables: <Scope>.EditorText.<lang>.json in an Editor folder; nested objects flatten to dotted keys. Found by AssetDatabase.FindAssets("EditorText t:TextAsset"), reloaded by KitTextPostprocessor on any change. Keys start with the module id (core., inventory.); the kit's own with kit.. One key per sentence, {0} placeholders; never concatenate translated pieces. A key defined twice logs a warning.
  • Not the game's localization (CSV tables, LocalizationManager): editor assets only, never in a build.

Help

KitHelp.Handler (set by a manual window), KitHelp.CanOpen, KitHelp.Open(page). A HelpPage is chapter-id or chapter-id#anchor; anchors are slugged from the heading text, so a translated chapter writes the anchor explicitly — ## Сцены {#scenes} (KitManualChapter.Anchor(heading, out text); the tag is stripped from the rendered title and the search text). Setup checks: KitSetupCheck.Rescan / RequestRescan() (raised by Check again and after a fix — cache expensive scans until then) and EvaluateSafely() (the try/catch around Evaluate).

Rules when writing a kit window

  1. Derive from KitWindow; build everything in BuildContent; state in [SerializeField] fields.
  2. No user-visible literal — every text is a key in the package's *.EditorText.en.json.
  3. Colors only from --kit-* variables; the single inline color is a module's Accent. State is a KitTone.
  4. Style with classes in a package .uss added by KitTheme.AddSheet; inline style.* only for runtime values.
  5. One primary button per view; KitEmptyState for empty views; KitCallout with a fix for problems; KitButtonKind.Danger + KitDialog.ConfirmDelete for destructive actions; toasts only confirm.
  6. Nothing per frame: rebuild on events, throttle live views (≤ 4 Hz), ListView for long lists, cache TypeCache/AssetDatabase lookups and clear them from an AssetPostprocessor.
  7. ScrollView.ScrollTo only after layout (schedule it and check layout.height > 0).
