class  CORE.Shared.Inputs.Players.PlayerService
 Local multiplayer (since v1.3): up to InputPlayersSettings.MaxPlayers players, each with a gamepad, a navigation context and a UI focus of their own; keyboard and mouse always belong to the primary. While the primary plays alone nothing of this costs anything — no UnityEngine.InputSystem.Users.InputUser, no copy of the assets, the host routes devices as usual. The first Join or EnableJoining pairs the primary too; when the last player leaves and joining is off, the single-player path is back. Joins and leaves requested inside an input update (from an action callback) are queued to the next tick. Reached through InputHost.Players. More...
