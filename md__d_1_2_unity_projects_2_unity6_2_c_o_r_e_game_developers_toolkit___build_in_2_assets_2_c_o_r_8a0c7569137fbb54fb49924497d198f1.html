Input System

CORE.Shared.Inputs.InputSystem — a layer over Unity Input System. Two kinds of action assets:

  • CORE's own, Assets/COREToolkit/Resources/InputSystem_Actions.inputactions (maps Player, UI, Debug, VirtualCursor since v1.3); Unity generates its C# wrapper Scripts/Shared/Inputs/GameInputActions.cs (do not hand-edit). A package update overwrites both — a game never adds its maps there.
  • The game's own .inputactions, listed by an InputProjectSettings asset in any Resources folder (Create/CORE/Input/Input Project Settings, any name, any number — a game and every package declare their own and all are merged, like PlayerResourceSettings; CORE's asset is always included). The Setup Wizard check Input: project settings creates Assets/Resources/InputProjectSettings.asset with an empty Assets/Settings/Input/GameInputActions.inputactions; it also warns about a map name used twice across the assets and about a package-owned asset listed by the game. At run time each game asset is served as a copy (InputSystem.GameAssets); FindActionMap(name) finds a map in any asset.

CORE code generation (Game Window → Resources → Generate) turns every action map of every asset into an InputKeyGenerated.InputGroups flag (PLAYER, UI, DEBUG, the game's, plus NONE/ALL) and every action into InputKeyGenerated.InputEnums.<MAP>_<ACTION> (PLAYER_JUMP, CAMERA_ZOOM). Existing members keep their values; a name is upper-cased and every character that is not a letter, digit or _ becomes _ ("Look Around" → LOOK_AROUND, a map starting with a digit gets a leading _); a map or action whose name collides after that (or a map called None / All) is skipped with a warning naming both. InputEnums.cg.cs is CORE's generated file, overwritten by a package update: run Generate once after updating (the game's members come back with the same values).

InputSystem is a plain class (IUpdateListiner, IDisposable) bound by ProjectInstaller with FromNew().AsSingle().

Subscribing, releasing, polling. No provider class is needed: the first use of a group creates an InputMapProvider for its map (CORE's or the game's).

[Zenject.Inject] private InputSystem _inputSystem;
private void Awake()
{
_inputSystem.RegisterAction(InputKeyGenerated.InputEnums.PLAYER_JUMP, Jump); // performed
_inputSystem.RegisterAction(InputKeyGenerated.InputEnums.ITEMS_SPLIT, OnSplitDown, OnSplitUp); // + canceled
}
private void Update()
{
if (_inputSystem.IsPressed(InputKeyGenerated.InputEnums.SELECTION_MULTI)) … // held this frame
_inputSystem.WasPressedThisFrame(input); _inputSystem.WasReleasedThisFrame(input);
var move = _inputSystem.ReadValue<Vector2>(InputKeyGenerated.InputEnums.CAMERA_MOVE);
var zoom = _inputSystem.ReadValue<float>(InputKeyGenerated.InputEnums.CAMERA_ZOOM);
}
private void OnDestroy()
{
_inputSystem.UnregisterAction(InputKeyGenerated.InputEnums.PLAYER_JUMP, Jump);
_inputSystem.UnregisterAction(InputKeyGenerated.InputEnums.ITEMS_SPLIT, OnSplitDown, OnSplitUp);
}

Typed providers stay for those who want the generated callbacks: derive from InputProviderBase, implement GameInputActions.I<Map>Actions, forward every callback with Invoke(InputEnums, context) (performed → pressed subscribers, canceled → released ones). The constructor takes GameInputActions — RegisterProvider<T> builds it via Activator.CreateInstance, not through DI. One provider per group: a typed one registered after the generic InputMapProvider of its group takes its subscriptions over; a second typed type for a served group throws InvalidOperationException. A provider's Register throws if the input belongs to another group. RegisterProvider(group) returns the group's provider (created on demand), UnregisterProvider(provider) drops it. DebugInputProvider (DEBUG) is registered by CORE itself; Examples/Scripts/Shared/ExampleInputProvider.cs is the reference for PLAYER, Examples/Scripts/InputsExample.cs for the examples' own Example map (Examples/Inputs/ExampleInputActions.inputactions, listed by Examples/Resources/InputProjectExamples.asset). Always unsubscribe.

Pointer and keyboard without UnityEngine.Input: _inputSystem.Pointer — Position, Delta (mouse, or the first touch), Scroll (y is the wheel: compare the sign, a notch is ±120 on Windows), IsPressed(PointerButton.Left), WasPressedThisFrame, WasReleasedThisFrame, TouchCount, HasMouse; _inputSystem.Keyboard — Shift, Ctrl, Alt, IsPressed(Key), WasPressedThisFrame(Key). Buttons, scroll, touches and keys read as released while everything is restricted (IsBlocked); the position is always read, the UI needs it. A bound action is still the better tool: it is rebindable and restricted per group.

Other members: RestrictedGroups, TryGetProvider(group, out provider), GetAction(input) (Unity InputAction of any asset or null), GetBindingDisplayString(input, bindingIndex), StartRebinding(input, bindingIndex, onComplete, onCancel) (Escape cancels; stores the override in Settings.Controls), ResetBindings(input), ApplyBindingOverrides(), SubscribeInvokeKeyListener / UnsubscribeInvokeKeyListener. Extensions in InputExtensions.cs: input.ToInputGroups(), input.ToActionName(), group.ToActionMapName(), group.HazFlag(other).

Restricting groups. IInvokeKeysListiner.CanActivateInvokeKey() returns (bool OverrideValue, InputKeyGenerated.InputGroups RestrictedGroup). Each update InputSystem ORs the restricted groups of all listeners (OverrideValue == true restricts ALL) and disables the action maps of restricted providers: their callbacks stay silent, their polls read released and zero. SaveSystem returns (IsActive, NONE) — everything is blocked while saving; so is it while the console is open (ConsoleHub.IsOpen). Code still on UnityEngine.Input or reading Keyboard.current itself is not blocked by any of this — gate it on ConsoleHub.IsOpen / InputSystem.RestrictedGroups.

Rebinding & persistence. User bindings are ControlInputSetting.BindingOverrides (BindingId GUID from the .inputactions asset + control Path) in Settings.Controls. InputSystem applies them on settings load and on every ControlSettingsData.OnApplied to every asset; after StartRebinding/ResetBindings call Settings.Apply() to save. ControlSettingsData.Migrate treats the config as the source of truth: new controls are added, removed ones dropped, user overrides kept. ControlInputSetting.Action is serialized as the enum's name, so regenerated numbers do not matter.

The game's controls page. Controls.ControlSettings of Resources/Configs/settings.json lists CORE's sample controls (Cancel, Debug_*, Jump, Move, Attack; their texts are in Core.csv). A game ships its own list in a settings.<part>.json fragment: an array in a fragment replaces the base array, so the game's Controls.ControlSettings replaces the samples entirely; "ControlSettings+": [...] appends to them instead. No Hidden flag is needed. Settings.DefaultSettings is built from the merged SettingsConfig.Config, fragments included: a new player and every Reset get the game's controls and Game fields, not the base file's.

Key icons from bindings. GetBindingIcon(input, bindingIndex, ResourcesGenerated.InputSizes) is the sprite of the binding's control (<Keyboard>/i → KeyCode.I → UI_Icon_I_<size> of the Input resource entry), the user's override included; null when the control is no key (a stick, an axis) or no sprite of that size is declared. GetBindingPath (effective control path; index -1 = the first control binding), GetBindingKeyCode, GetControlBindingIndexes(input, list) (the indexes that are controls, composite parts included — what to pass to StartRebinding). The table is InputControlPaths: ToControlPath(KeyCode) / ToKeyCode(path) — also the one-time migration of a game's KeyCode data into bindings; gamepad buttons follow the Xbox layout of KeyCode.JoystickButton*. The legacy ResourcesGenerated.LoadSpriteInput(KeyCode, InputSizes) still works.

Migrating a game from UnityEngine.Input. Keep Player Settings → Active Input Handling on Both while old polling remains (CORE itself never uses the legacy API), switch to Input System Package at the end. While the console is open the scene's EventSystem is disabled: a per-frame "pointer over UI" check must handle EventSystem.current == null.

Gamepad support (since v1.3)

Input modes, UI navigation by layers, groups and elements, prompts and icons, the virtual cursor, haptics, rebinding, Steam Deck readability, local multiplayer, debugging and the Input Editor live in references/gamepad.md — start there for anything about a gamepad, InputHost or UIInput*.

Audio

CORE.Shared.Audio.IAudioService (injected, bound in the project context) plays every sound, whatever engine is behind it. Sounds are AudioKeys — string ids compared case-insensitively, serialized as the id, generated as AudioKeys.<Name> (CORE.Shared.Generated.Audio) by Game Window → Resources → Generate.

[Zenject.Inject] private IAudioService _audio;
var handle = _audio.Play(AudioKeys.UI_MouseSingleClick_0);
_audio.Play(AudioKeys.Door_Open, new AudioPlayOptions { Position = transform.position, Volume = 0.8f });
_audio.Play(key, new AudioPlayOptions { Follow = transform, FadeIn = 0.5f, Loop = true, Priority = 0 });
_audio.Play(key, new AudioPlayOptions { Follow = transform, MinDistance = 5f, MaxDistance = 120f, FollowEndFade = 0.3f });
_audio.Stop(handle, fade: 0.5f); // a stale handle is ignored
_audio.SetVolume(handle, 0.3f, fade: 1f); _audio.SetPaused(handle, true);
_audio.SetParameter(handle, "pitch", 1.2f); // Unity backend: volume, pitch; an FMOD backend: event parameters
_audio.SetBusVolume(AudioBus.Music, 0.5f); // game-side scale × the player's volume from the settings
_audio.SetBusPaused(AudioBus.Effects, true);
_audio.SetSnapshot("Underwater", true); // a mixer snapshot (Unity) or snapshot event (FMOD) mapped in the backend asset
_audio.PlayClip(clip, AudioBus.Interface); // a clip outside the catalog (localized clips)
_audio.Music.Play(AudioKeys.Music_GoblinsDenRegular); // crossfades, loops (also when it is the playlist's current track)
_audio.Music.PlayPlaylist(tracks, shuffle: true); _audio.Music.Next(); _audio.Music.Stop();
  • Buses — AudioBus ids: Master, Interface, Music, Effects built in; a game adds its own by id. The player's volume per bus is Settings.Audio.GetVolume(bus) / SetVolume(bus, 0..100) (CORE's four buses are the OverallVolume, InterfaceVolume, MusicVolume, EffectVolume fields, others BusVolumes); the service applies it to the backend on every settings change (SetVolume raises OnChanged, so a slider is heard at once). Slider → dB is 20·log10(v/100) (AudioMath). A settings screen that edits a copy until Apply calls PreviewSettings(copy) after every slider move: the copy's volumes are heard until EndPreview() (close / cancel) or until the applied settings change (SetData, SetVolume), which ends the preview by itself; IsPreviewing. The legacy AudioSystem.Apply(copy) forwards to it.
  • 3D — a Spatial cue played with Position or Follow: MinDistance / MaxDistance of the cue, or of the options for one play (the same loop at different ranges from different objects); Rolloff — Logarithmic (Unity's default, never silent: past the max distance the sound stays at min / max), Linear, LogarithmicCutoff (the log curve cut to silence at the max distance — the usual choice for looped world sounds, which otherwise stay faintly audible and keep a voice across the whole map), Custom with AudioCue.RolloffCurve for cues registered from code (time 0–1 = distance / max). An FMOD event carries its own attenuation; the distance options still apply to it. Follow: once the followed transform is destroyed the instance stops (FollowEnd — Stop for a loop, Keep for a one-shot unless set; FollowEndFade seconds) and, with StopWhenFollowInactive, also while the object is inactive in the hierarchy, like an AudioSource on it.
  • Muting — a one-shot on a muted bus (its volume or the master at 0) is skipped and returns an invalid handle; loops and music start silent, so they are heard once the player unmutes.
  • Catalog (AudioCatalog, static) — what a key resolves to, later wins:
    1. every clip of an AudioClip resource entry, keyed by its file name; its bus by AudioProjectSettings.BusRules (UI_ → Interface, Music_ → Music, else DefaultBus);
    2. cues of Resources/Configs/audio.json (AudioCueConfig : ConfigList, fragments audio.<part>.json): "Footstep": { "Clips": ["Footstep_0", "Footstep_1"], "Bus": "Effects", "PitchMin": 0.9, "PitchMax": 1.1, "Spatial": true, "MaxDistance": 30, "Rolloff": "LogarithmicCutoff", "MaxInstances": 3, "Cooldown": 0.05 } — Clips are clip names, one is picked per play; an id equal to a clip name overrides how that clip plays;
    3. runtime: AudioCatalog.Register(cue | clips, owner, priority) / Unregister(owner) — mods register the clips of their audio bundle by name.
  • Backend — AudioProjectSettings holds the AudioBackendAsset. The game's own asset, Assets/Resources/AudioProjectSettings.asset (AudioProjectSettings.AssetName, outside the package), wins; without one the game runs on CORE's defaults, Assets/COREToolkit/Resources/AudioProjectDefaults.asset (DefaultsName), which a package update overwrites — so never edit the defaults or the package's backend assets for a game: the Setup Wizard check Audio: project settings (or the Audio Editor's Buses page) creates the game's own from the defaults with a copy of the backend asset under Assets/Settings/Audio/. CORE's backend is UnityAudioBackendAsset (Settings/UnityAudioBackend.asset): the AudioMixer, bus → mixer group + exposed volume parameter, snapshots, MaxVoices (out of voices the least important instance is replaced: one fading out first, then a one-shot before a loop, then the higher Priority number, then the oldest; music plays at priority 0 — a pool of AudioSources under the persistent CORE Audio object, which also carries the AudioListener). A third-party engine is an IAudioBackend + its AudioBackendAsset; IAudioService.TryGetNative<T> reaches the engine object (the mixer for Unity).
  • FMOD backend — ships in the package (Scripts/Shared/Audio/FMOD/, asmdef Game_AudioFMOD_AD, namespace CORE.Shared.Audio.FmodBackend) and compiles only with the CORE_FMOD define; no FMOD backend asset ships (it would be a missing script without FMOD). Import FMOD for Unity (2.02+), then the Setup Wizard check Audio: FMOD backend → Enable: adds CORE_FMOD to every build target, and after the recompile creates FmodAudioBackend.asset next to the game's own backend asset (under Assets/Settings/Audio/ when there is none) and assigns it in the game's own AudioProjectSettings, created on demand. Remove the define undoes it — a CORE_FMOD left after deleting FMOD breaks compilation. FmodAudioBackendAsset:
    • a key plays the event of its Events mapping (Key → EventReference, optional Bus), otherwise its id is the path: new AudioKey("event:/UI/Click") or "UI/Click" (prefix added). Has(key) / CanPlay need no catalog cue. A key with no event but a catalog cue with clips, and every PlayClip, play through a Unity backend next to FMOD (ClipBackend, or a mixer-less pool with an AudioListener if ClipListener).
    • Buses: AudioBus → bus:/… (bus:/ is master) or vca:/… (volume only); defaults bus:/, bus:/UI, bus:/Music, bus:/SFX. A path not found (bank not loaded yet) scales CORE's instances until it appears — retried every second, warned once.
    • Snapshots: id → snapshot event; an unmapped id plays snapshot:/<id>. SetSnapshot(id, false) stops it.
    • Banks loaded on start; AllowFadeOut (stop lets the event's AHDSR/release play); CreateListener puts a StudioListener on the CORE Audio (FMOD) root.
    • SetParameter = EventInstance.setParameterByName (volume / pitch if the event has no such parameter); SetGlobalParameter = Studio global parameter. Volume, Pitch, Position / Follow (3D events, with FollowEnd), MinDistance / MaxDistance (the event's min / max distance properties), Delay, FadeIn and fades of Stop / SetVolume apply; Loop and Bus options only file the instance for StopAll and pausing — looping and routing are authored in FMOD. The bus of an instance is the option's, the mapping's, the cue's, or the event's first folder matched to a bus id or bus path name (event:/Music/… → Music).
    • StopAll stops only instances CORE started (not StudioEventEmitters).
    • FMOD handles are structs, so TryGetNative<T> returns the backend itself: if (_audio.TryGetNative<FmodAudioBackend>(out var fmod) && fmod.TryGetInstance(handle, out var instance)) …; fmod.StudioSystem is RuntimeManager.StudioSystem.
    • Inspector: the AudioKey picker lists the FMOD events of FMOD's event cache under FMOD (by folder) and the keys of every backend asset's Events under FMOD/Mapped (editor asmdef Game_AudioFMODEditor_AD in FMOD/Editor/, also behind CORE_FMOD); UI/Click counts as event:/UI/Click. Refresh banks in FMOD if a new event is not listed.
  • AudioKey inspector — a picker of catalog clips and cues (grouped by the name's start, ▶ previews a clip), the keys of every AudioKeySource, and Custom key… to type any id (Enter keeps, Escape drops). A key nobody knows is red (missing) — a warning only, it still plays if the backend has it. Another middleware adds its keys with an editor class deriving from CORE.SharedEditor.AudioKeySource (parameterless constructor, found by type): Name (top group), GetEntries() → new AudioKeyCache.Entry(key, Name, "Folder/Sub", tooltip), Version (change it to rebuild the cache), Resolve(key) for alternative spellings.
  • Listener — follows Camera.main (AudioProjectSettings.ListenerFollowsMainCamera) unless SetListenerTarget(transform) gives another target (null — back to the camera). It is a child of the audio root.
  • Game pause — the buses of AudioProjectSettings.PauseWithGame (Effects by default) pause while PauseSystem.IsPaused; SetBusPaused from code is held separately, a bus plays once neither holds it.
  • Memory — clips load on first play and stay cached; Preload(keys…) behind a loading screen, Unload(keys…) / UnloadUnused() after a level (a playing sound keeps its data; FMOD: event sample data).
  • Saving volumes — Settings.Audio.SetVolume applies at once; Settings.Save() writes the settings file.
  • Music on start — AudioProjectSettings.PlayMusicOnStart plays Playlist (empty: every cue on the Music bus), shuffled, crossfading MusicCrossfade seconds. L skips a track in the editor and development builds.
  • Audio Editor — Tools/CORE/Audio Editor: every key with preview and waveform, cue editing (written through the Config Editor's model into the file that decides each value; new cues into a chosen file, by default the game's Assets/Resources/Configs/audio.assets.json fragment — never into a package's file), rename with references (AudioKey fields only), usages, buses and backend, problems. A save that changes the keys regenerates AudioKeys. In the Config Editor, Clips and Bus of a cue have pickers (ConfigChoicesAttribute.AudioClip / AudioBus).
  • Debugger — page Audio: the backend, the catalog, and in play mode the buses, the music and every playing instance with Stop.

For prefab-driven sound, put an AudioComponent on a Selectable: AudioClip.Selections map a state (Pressed, Highlighted…) to a Key, OverrideVolume, Loop; AudioClip.Bus overrides the cues' bus. CustomButton / CustomToggle / CustomSlider / CustomDropdown call Play(state) themselves.

Legacy (obsolete, removed in 1.4.0 — LegacyAudio.RemovedIn). AudioSystem (PlayClip, StopClip, SetGlobalVolume, PlayLocalizedClip, AudioGroups), AudioLibrary / AudioLibrary.AudioClipData and the sub-systems still compile and forward to IAudioService; BootBase._audioSystem stays next to the new BootBase._audio. AudioSelectionData.Groups / Clip / Version are upgraded to Key in play mode; Tools/CORE/Setup Wizard → Migrations → Audio (Setup Wizard check Audio: AudioKey) rewrites prefabs and scenes for good. A legacy clip's key is its file name: (UI, MouseSingleClick, _0) → UI_MouseSingleClick_0. The update overwrites Scripts/Shared/CodeGenerated/ResourcesAudioAudioClip.cg.cs with CORE's: a game whose own clips were in those enums restores its pre-update copy (the prefabs hold the numbers) before migrating, and declares its clips in a copy of CORE's Audio entry in its PlayerResourceSettings.

Game Settings

CORE.Shared.GameSettings.Settings (static) is the live, persisted user settings; defaults come from SettingsConfig: Settings.DefaultSettings is SettingsData.FromConfig(SettingsConfig.Config) — settings.json with every settings.<part>.json fragment applied — so a new player, a page's Reset (SetData(Settings.DefaultSettings.Game)) and the migration of an old Settings.json all use the same values.

Settings.Controls; // ControlSettingsData

Persisted to {persistentDataPath}/Settings.json (Settings.FileName); the player profile UserData is a separate file, Saves/UserData.json — see save.md.

  • GameSettingsData: Language, AutoSave (TimeSpan, bounded by Min/MaxAutoSaveMinutes), UIScaleFactor (Min/MaxUIScaleFactor, UIScaleFactorNormalized), BorderMoveSystem, SteamClouds, HasApplyiedSteamLanguage.
  • GraphicSettingsData: Resolution, FpsLimit, Ration, Display, FullScreen, VSync, Brightness, Gamma, CurrentPreset, QualityPresetSettings, CustomQualityPresetSettings, ApplyResolution(), GetCurrentDisplayInfo. Supports Built-in RP, URP and HDRP.
  • AudioSettingsData: OverallVolume, InterfaceVolume, MusicVolume, EffectVolume, BusVolumes, GetVolume(bus) / SetVolume(bus, 0..100), NotificationSound, GetAudioVolume(borders, sliderValue) — slider 0–100 to mixer dB along 20·log10(value/100) (100 → 0 dB, 0 → borders.x), since v1.2; it was linear −80..+20 dB before.
  • ControlSettingsData: ControlSettings (ControlInputSetting[]: IdKey, Action (InputEnums), BindingOverrides, IsCombination, localization keys LocalizeName / LocalizeDescription / LocalizeTooltip with NameKey / DescriptionKey / TooltipKey; Group derives from Action).

All four derive from BaseSettingsData with Validate(), Apply(), SetData, Migrate, CheckIdentity, plus OnApplied / OnChanged events. After mutating a value, call the relevant consumer (_uiScaler.OnGameSettingsChanged(Settings.Game); audio applies itself) or Settings.Apply().

Graphics quality presets

GraphicSettingsData.Apply() does, in order: ApplyResolution() (Screen.SetResolution with Resolution, FullScreen, refresh rate), Application.targetFrameRate = FpsLimit, QualitySettings.vSyncCount, QualitySettings.SetQualityLevel((int)CurrentPreset), then CurrentQualitySettings.Apply().

  • CurrentPreset is GameSettingsPreset (LOW, MEDIUM, HIGH, ULTRA, CUSTOM). Its index is used as the Unity quality level, so the project's Quality Settings must have at least four levels in the same order.
  • QualityPresetSettings[] are the per-preset blocks, authored in Resources/Configs/settings.json (SettingsConfig.Graphics); CustomQualityPresetSettings is the user-editable copy (starts as a clone of ULTRA). CurrentQualitySettings picks between them; GetQualityGamePreset(preset) looks one up.
  • QualityPresetSetting (Configs/Settings/Data/): TextureQuality (QualityLevel → globalTextureMipmapLimit), ShadowQuality, ShadowVisibility (shadow distance, clamped 60..350), HBAO, SSR, AnisotropicFiltering, and under #if ENABLED_URP Antialiasing (MsaaQuality) with GetMsaaValue() / GetShadowResolution(). HBAO and SSR are stored and compared but not applied by CORE — hook your post-processing to them yourself.
  • Under URP Apply() writes shadowDistance / msaaSampleCount on the active UniversalRenderPipelineAsset and the main-light shadow resolution through UnityGraphics.

UnityGraphics (CORE.Shared.Utils, #if ENABLED_URP only) exposes the private URP asset fields via reflection as static properties: MainLightCastShadows, AdditionalLightCastShadows, MainLightShadowResolution, AdditionalLightShadowResolution, Cascade2Split, Cascade4Split, SoftShadowsEnabled, DefaulRendererIndex, RendererDataList. It mutates the asset, which in the editor persists past play mode.

ENABLED_URP / ENABLED_HDRP are version defines of Game_Shared_AD.asmdef, present only while the package is installed (see setup.md); every URP-specific line must be guarded by them.

Other members: FPSLimit (FPS_MAX = -1, 30, 60, 75, 120), AspectRation (only RATION_16x9), Display + GetCurrentDisplayInfo, Brightness / Gamma (10..100, stored only — apply them in your own post-processing), ResolutionHelper (JSON-safe Resolution with RefreshRateHelper).

Pooling

CORE.Shared.Utils.Pool:

var pool = new Pool<Bullet>(createNew: () => new Bullet(), onGet: b => b.Reset(), onRelease: null);
var bullet = pool.Get();
pool.Release(bullet);
using (pool.Get(out var b)) { } // Handle : IDisposable, auto-release
pool.Get(count, collection);
pool.TotalCount / PooledCount / ActiveCount; pool.Clear();

StaticPool<T> and StaticCollectionPools give shared per-type pools (Get, Release, Get(out ...)). UI-internal helpers ListPool<T> and ObjectPool<T> also exist.
