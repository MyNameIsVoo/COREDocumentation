Namespaces: CORE.Shared.UI.VisualView, CORE.Shared.DI, CORE.Shared. Source: Assets/COREToolkit/Scripts/Shared/UI/VisualView/, DI/, GlobalUpdater.cs, PauseSystem.cs, GameApplication.cs, BootBase.cs.

The pattern

VVM = Visual (MonoBehaviour: scene references only, zero logic) + View (plain C# class: all logic, constructed through Zenject).

// Visual — holds inspector references, creates the View, nothing else.
public class MyScreenVisual : Visual
{
public TextComponent Title;
public CustomButton CloseButton;
private MyScreenView _view;
protected override void Create(IView view)
{
_view = DiContainerRef.Container.Instantiate<MyScreenView>(new object[] { this });
base.Create(_view);
}
}
// View — logic. Constructor arg order must match the object[] passed to Instantiate.
public class MyScreenView : View<MyScreenVisual>
{
[Zenject.Inject] private AudioSystem _audioSystem; // extra deps come from the container
public MyScreenView(MyScreenVisual visual) : base(visual) { }
public override void Setup() // once, immediately after the View is registered
{
base.Setup();
Visual.CloseButton.EventClick += OnCloseClicked;
}
public override void Awake() // once, on the NEXT GlobalUpdater tick (see below)
{
base.Awake();
}
public override void Update() // every frame while active and not pause-blocked
{
base.Update();
}
public override void Sleep() // teardown — mirror of Setup
{
base.Sleep();
Visual.CloseButton.EventClick -= OnCloseClicked;
}
private void OnCloseClicked(CustomButton button) { }
}

base.X() calls matter: View.Awake() sets HasBeenAwakened, Sleep() clears it, OnHide() bumps _openId, Subscribe/Unsubscribe register with GlobalVisual. Always call the base.

Exact lifecycle

Read Visual.cs + GlobalVisual.AddView if you need to be sure. The order is:

Unity/CORE step What happens
Visual.Awake() Create(null) if View == null → your override builds the View → base.Create stores it → View.Subscribe() → GlobalVisual.AddView(...) → View.Setup() runs synchronously → View.Awake() is enqueued (runs on the next GlobalVisual.DoUpdate, i.e. next frame) → DidAwake = true
Visual.OnEnable() View.OnShow()
every frame GlobalVisual.DoUpdate() drains the awake queue, then calls View.Update() for each view where View.IsActive && (!PauseSystem.IsPaused \|\| !View.PauseDependent)
Visual.OnDisable() View.OnHide()
Visual.OnDestroy() early-returns if GameApplication.AppQuit; else View.Unsubscribe() → GlobalVisual.RemoveView → View.Sleep() → View.Destroy()

Consequences you must design around:

  • View.Awake() is one frame late. Anything another script needs immediately (e.g. Tabs.TabsView.OnValueChanged) must be hooked in Start(), not Awake(), or you must call visual.ForceCreate() first. Examples/Scripts/CustomUIExample.cs documents exactly this. Exception: while PauseSystem.IsPaused, Awake() runs synchronously.
  • Setup() is the reliable "constructor-ish" hook — it runs synchronously inside Visual.Awake. Subscribe to UI events there and unsubscribe in Sleep().
  • View.FixedUpdate() is never called by CORE. GlobalVisual.DoUpdate only calls Update(). To get fixed updates, implement IFixedUpdateListiner on the View and call _globalUpdater.SubscribeFixedUpdate(this, data) / UnsubscribeFixedUpdate yourself.
  • View.Destroy() never fires on application quit (the AppQuit guard in Visual.OnDestroy). Do not rely on it to flush data — use GameApplication.OnAppQuit.

Visual fields are a non-null contract

A serialized reference on a Visual — GameObject, Transform, RectTransform, CustomButton, TextComponent, another Visual, anything wired in the prefab — is guaranteed non-null. The View must never check it.

public class ContextMenuVisual : Visual
{
public CustomButton Backdrop; // contract: always wired
public RectTransform Panel; // contract: always wired
[CanBeNull] public TextComponent Header; // genuinely optional — checking is allowed
}
// ❌ in the View — forbidden for a field without [CanBeNull]
if (Visual.Panel == null)
return;
Visual.Header?.SetText(text);
var t = Visual.Backdrop != null ? Visual.Backdrop.transform : null;
// ✅ just use it
Visual.Panel.pivot = Vector2.zero;
Visual.Backdrop.EventClick += OnBackdropClicked;
// ✅ allowed, because the field is marked
if (Visual.Header != null)
Visual.Header.SetText(text);

Why:

  • An unwired reference is a prefab authoring bug. A null check converts a loud NullReferenceException with a stack trace pointing straight at the field into a screen that silently renders half of itself — the most expensive class of bug to find.
  • Once one consumer defends, every consumer defends, and the code no longer says which references are actually optional. [CanBeNull] is the only signal that carries that meaning.
  • ?. and ?? are wrong on UnityEngine.Object anyway: they use reference null, bypassing Unity's overloaded ==, so a destroyed object passes ?. and then throws inside. Never reach for them to "safely" touch a Visual field.

[CanBeNull] is JetBrains.Annotations, bundled in UnityEngine.CoreModule — add using JetBrains.Annotations;, no package or asmdef reference needed.

If you want the missing reference caught earlier than the first frame, validate at authoring time instead of defending at runtime — that is what OnValidate and CORE's ValidationUtility.SafeOnValidate(Action) / ValidationUtility.IValidator are for.

The same contract applies in the other direction: do not [CanBeNull] a field just to silence a warning. If it is optional, the View must handle both branches meaningfully; if it is not, wire it in the prefab.

VisualNames is generated into Scripts/Shared/CodeGenerated/Visuals.cg.cs from prefab names: prefabs named UI_<NAME>_... containing Screen or Modal produce VisualNames.<NAME>. Adding a new named screen requires re-running code generation.

Other Visual members: View, IsActive, DidAwake, ForceCreate(), Show(), Hide(), Destroy().

Base type Use for

Overridable flags on View<T>:

  • PauseDependent (default true) — set false so Update() keeps running while paused.
  • UpdateOnDisabled (default false) — keep updating while the GameObject is inactive.

GlobalVisual

GlobalVisual is the registry of all live Visual/View pairs and the thing that drives View.Update(). It is bound in ProjectInstaller and injected into every View<T> as _globalVisual.

[Zenject.Inject] private GlobalVisual _globalVisual;
_globalVisual.GetVisual<MyScreenVisual>();
_globalVisual.TryGetVisual<MyScreenVisual>(out var visual);
_globalVisual.HasVisual<MyScreenVisual>();
_globalVisual.Show(VisualNames.SETTINGS);
_globalVisual.Show(VisualNames.CONFIRM, new ConfirmationModalViewData { ... });
_globalVisual.Hide(VisualNames.SETTINGS);

Show(name)/Hide(name) only work for visuals listed in the GlobalVisual._visuals inspector array. Show(name, data) additionally requires the View to implement IViewData (i.e. derive from View<T, TData>).

GetVisual<T> is a FirstOrDefault over a dictionary — do not call it per frame. Cache with CashedVisualValue<T> (note the typo in the class name) or CachedValue<T>:

private readonly CashedVisualValue<MyScreenVisual> _screen;
_screen = new CashedVisualValue<MyScreenVisual>(_globalVisual);
_screen.Visual.Show();

GlobalVisual also implements IModSupportVisual (GlobalModVisual.cs) — see mods.md.

Dependency injection (Zenject / Extenject)

  • DiContainerInstaller publishes the container to the static DiContainerRef.Container (plus DiContainerRef.OnInitted).
  • ProjectInstaller binds the core singletons with BindInterfacesAndSelfTo<T>(): GlobalUpdater, GlobalVisual, AudioSystem, SaveSystem, CustomCursor, SaveComponentsManager, Dispatcher, UIScaler .FromInstance(...) (fields on the prefab); InputSystem .FromNew() (plain class, no prefab field).
  • The game's project-wide bindings go into Resources/PlayerProjectContext.prefab (PlayerProjectContext: Bindings, Installers), installed after ProjectInstaller — see setup.md.
  • Field injection is the house style: [Zenject.Inject] private SaveSystem _saveSystem; (fully-qualified attribute, no using Zenject;). CORE uses this in MonoBehaviours, Views and plain classes alike.
  • Constructing a non-MonoBehaviour with dependencies: DiContainerRef.Container.Instantiate<T>(new object[] { ctorArg0, ctorArg1 }).
  • To bind your own systems, add a MonoInstaller like Examples/Scripts/BootInstallerDI.cs and attach it to the scene context.

DiContainerRef.Container is null until the installer runs. Anything touching it in a RuntimeInitializeOnLoadMethod or a very early Awake must guard or wait (GlobalVisual.Start does yield return new WaitUntil(...)).

Creating things through the container

Everything new goes through the container. new on a type with injected members and Object.Instantiate on a prefab both skip injection — the object is created, [Zenject.Inject] fields stay null, and the failure shows up later as a NullReferenceException far from the cause.

What you are creating Use
plain C# class with ctor args (View, save component, service) Container.Instantiate<T>(new object[] { arg0, arg1 })
plain C# class, no ctor args Container.Instantiate<T>()
prefab, you need the GameObject Container.InstantiatePrefab(prefab) / (prefab, parent)
prefab, you need a component on it Container.InstantiatePrefabForComponent<T>(template) / (template, parent)
prefab whose component type is known only at runtime Container.InstantiatePrefabForComponent(type, template, parent, new object[0])
component on an existing GameObject Container.InstantiateComponent<T>(gameObject)
component on a brand-new GameObject Container.InstantiateComponentOnNewGameObject<T>()
prefab declared in ResourceSettings / PlayerResourceSettings the generated Load* method — it already calls InstantiatePrefab

CORE follows this without exception; these are its own call sites and the patterns to copy:

// View from its Visual — Visual.Create overrides, TimerDefaultVisual, modals
_view = DiContainerRef.Container.Instantiate<MyView>(new object[] { this });
// dropdown item prefab -> component — CustomDropdown.cs:553
var item = DiContainerRef.Container.InstantiatePrefabForComponent<CustomDropdownItemVisual>(itemTemplate);
// table row, type comes from the data — CustomTableView.cs:156
var row = (CustomTableItemVisual)DiContainerRef.Container
.InstantiatePrefabForComponent(data.VisualType, template, _rootSpawnItems, new object[0]);
// tab page content under a parent — CustomTabsView.cs:38
item.Content = DiContainerRef.Container.InstantiatePrefab(Visual.ContentTemplate, parent);

Pooling is not an exception — put the container call inside the factory delegate:

// ✅ pooled objects are injected on creation
var pool = new Pool<ItemSlotVisual>(
() => DiContainerRef.Container.InstantiatePrefabForComponent<ItemSlotVisual>(prefab, _poolRoot));
// ❌ skips injection for every pooled instance
var pool = new Pool<ItemSlotVisual>(() => Object.Instantiate(prefab, _poolRoot));

Legitimate exceptions — do not route these through the container:

  • Pure data with no dependencies: Config subclasses, ViewData, SaveGameBaseComponentData, EnumData<T>, SerializableVector*, structs, plain DTOs. new is correct.
  • Copying a Unity asset rather than spawning an object: Instantiate(Material), Instantiate(ScriptableObject) — see LoadingIcon.cs:29.
  • Anything already returned by a generated Load* method or by ResourceComponent — injection happened inside the loader.

A Visual created with raw Object.Instantiate still appears to work, because its View is built from the static DiContainerRef inside Create. That is luck, not correctness: the moment anyone adds an [Zenject.Inject] field to that Visual or to any component on its prefab, it silently stays null. Use the container from the start.

GlobalUpdater, PauseSystem, GameTime

GlobalUpdater replaces per-MonoBehaviour Update() for framework-managed objects.

public class MySystem : MonoBehaviour, IUpdateListiner
{
[Zenject.Inject] private GlobalUpdater _globalUpdater;
private void Awake()
{
// pauseDependent: true -> stops while paused
_globalUpdater.SubscribeUpdate(this, new UpdateData(true, UpdateOrders.BeforeDefault));
}
private void OnDestroy()
{
_globalUpdater.UnsubscribeUpdate(this);
}
public void DoUpdate() { }
}

SubscribeUpdate calls DoUpdate() synchronously when GameApplication.HasBeenInitted, before the listener is stored. Subscribing from Awake therefore runs one update inside that Awake, while sibling components may not have run theirs yet. Anything read in DoUpdate must already be valid (initialize it in field initializers, not in another component's Awake). An exception there is fatal to the subscription: it escapes before the listener is added, so the object silently never updates again.

UpdateOrders: BeforeDefault = -1, Default = 0, AfterDefault = 1, AfterAll = 2. Fixed-update twin: IFixedUpdateListiner.DoFixedUpdate() + SubscribeFixedUpdate / UnsubscribeFixedUpdate.

PauseSystem is static: PauseSystem.IsPaused, PauseSystem.SetPause(bool), PauseSystem.OnChanged.

GameTime (CORE.Shared.Utils) is the pause-aware clock: GameTime.Time (accumulated unpaused seconds), GameTime.Now, GameTime.Utc. Prefer it over Time.time for gameplay timing.

Dispatcher marshals work onto the main thread and hosts global coroutines: Dispatcher.Enqueue(action, delayCall), Dispatcher.StartCoroutineGlobal(routine), Dispatcher.StopCoroutineGlobal(routine).

Boot sequence

GameApplication.Awake() (Scripts/Shared/GameApplication.cs) runs, in order:

  1. Single-instance Mutex guard (builds only).
  2. Steam init / WaitForSteamLaunch (standalone platforms only).
  3. ColorLibraryData.EnsureInstance(), ResourceSettings.EnsureInstance().
  4. ConfigSystem.Init() → ColorLibrary.Init() → Settings.Init() → Model.Init() → Settings.Apply().
  5. SteamAPI.RestartAppIfNecessary(GlobalConfig.Config.SteamId).
  6. await AssetBundlesManager.Init().
  7. Your hooks: OnAllSystemsInittedAsync (Task) and OnAllSystemsInitted (UniTask), each returning GameApplication.ResultData { IsOk, ErrorMessage }; progress is shown via ProgressVisual.
  8. SteamManager.Instance.InitServices(), rich presence, cloud flag.
  9. HasBeenInitted = true → ProgressVisual.Set("Completing initializing...", 3f) → OnInitted.

On quit: AppQuit = true → OnAppQuit → Model.User.TrySave() → cache/bundle cleanup.

To register a system that must be ready before gameplay:

[RuntimeInitializeOnLoadMethod(RuntimeInitializeLoadType.BeforeSplashScreen)]
private static void Init()
{
GameApplication.OnAllSystemsInitted += InitAsync;
}
private static async UniTask<GameApplication.ResultData> InitAsync()
{
await SomethingAsync();
return new GameApplication.ResultData(); // IsOk defaults to true
}

Scene entry point — derive from BootBase (gives you _audioSystem) and handle the already-initialized case, as Examples/Scripts/Boot.cs does:

protected override void Awake()
{
base.Awake();
GameApplication.OnInitted += OnInitted;
if (GameApplication.HasBeenInitted)
OnInitted();
}
private void OnInitted()
{
GameApplication.OnInitted -= OnInitted;
// safe to touch configs, resources, Model, Settings here
}
