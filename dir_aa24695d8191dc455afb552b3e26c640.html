Detailed Description

A portable UI Toolkit base for editor windows: theme, vector glyphs, components, texts, module identity and a window base class. Every editor window of CORE and of the plugins built on it is made from this kit, so they look the same, speak the same text tables and find each other's packages by themselves.

  • Assembly EditorKit_AD, namespace CORE.EditorKit, editor only.
  • References nothing but Unity and Newtonsoft Json (a Unity package). It does not know CORE: copy this folder into any project and it works. Keep it that way — never add a reference to Game_Shared_AD or any other assembly from here.
  • Works on Unity 2022.3 and Unity 6 (no textEdition.placeholder; KitInput.Placeholder draws its own).
  • Logging goes through the internal KitLog (prefixed [EditorKit]), the one place in CORE that does not use DebugHelper — the kit cannot reference it.

Open Tools → CORE → Editor Kit Gallery to see every component in the current skin and language.

A window in ten lines

using CORE.EditorKit;
using static CORE.EditorKit.KitText;
public sealed class BundlesWindow : KitWindow
{
[SerializeField] private string _page; // survives rebuilds and domain reloads
protected override string Title => Tr("core.bundles.title"); // every text is a key
protected override string HelpPage => "bundles"; // shown once a manual sets KitHelp.Handler
[MenuItem("Tools/CORE/Bundles")]
public static void Open() => GetWindow<BundlesWindow>();
protected override void BuildHeaderActions(VisualElement actions) => actions.Add(new KitLanguageButton());
protected override void BuildContent(VisualElement content)
{
var sidebar = new KitSidebar("core.bundles"); // folds remembered under this key
var scroll = KitPage.Scrolled(out var page, Tr("core.bundles.page"), Tr("core.bundles.lead"));
content.Add(sidebar);
content.Add(scroll);
var card = new KitCard(Tr("core.bundles.card"), KitGlyphs.Bundle, collapsible: true);
card.Content.Add(new KitRow(Tr("core.bundles.name"), new TextField()));
page.Add(card);
StatusBar.SetText(Tr("core.bundles.status", 3));
}
}

The five windows every package gets for free

Derive the frame, add a [MenuItem], and the window fills itself with what the installed packages contribute:

A plugin's windows override Includes(...) to show only its family; a host (CORE) shows everyone's.

Rules for a package built on the kit

  1. Declare one KitModule in the package's editor assembly: Id (prefix of its keys and glyphs), Title, AssemblyPrefix, Accent, Glyph, Order. Everything of the package is found through it — nothing is registered by hand. A family of packages (a base and its DLCs) shares a base class and lists itself with KitModule.AllOf<T>().
  2. Every window derives from KitWindow and builds its whole tree in BuildContent; it is rebuilt on a language change. State lives in [SerializeField] fields.
  3. No user-visible literal. Tr("<module>.<window>.<what>"); tables are <Scope>.EditorText.<lang>.json in an Editor folder, nested objects flatten to dotted keys. The kit's keys start with kit.. Placeholders are {0}; one key per sentence.
  4. Colors only from --kit-* variables. The one exception is a module's Accent, set inline on a tile, chip or card stripe. State is a KitTone, never a hard-coded color.
  5. Style with classes. A package's look lives in its own .uss next to its windows, added with KitTheme.AddSheet(root, "<FileName>"), BEM-named (block__element--modifier) and using only the kit's variables. Inline style.* only for values computed at runtime.
  6. Icons are glyphs. KitGlyphs.Register("<module>.<name>", "<path>") from an [InitializeOnLoadMethod]; grammar in KitGlyph. Unity's own icons through KitIcon.SetBuiltin where a Unity concept is shown.
  7. One primary button per view. Empty views show a KitEmptyState; problems a KitCallout with a fix; destructive actions are KitButtonKind.Danger and confirm through KitDialog; toasts only confirm.
  8. Fast by construction. Nothing per frame; rebuild on events, throttle live views, virtualize long lists with ListView, cache TypeCache/AssetDatabase lookups.

Coming from Inventory.Editor.Kit

The kit is the inventory plugin's editor kit made generic. To move a package onto it:

  • using Inventory.Editor.Kit; → using CORE.EditorKit; (and the using static … KitText;); delete the package's own Kit folder and its asmdef; reference EditorKit_AD instead of Inventory.Editor.Kit_AD.
  • InventoryEditorModule derives from KitModule; drop its own All/Find/Of and use KitModule.* (KitModule.AllOf<InventoryEditorModule>() where only the family is wanted).
  • Module colors and glyphs leave the kit: KitPalette.Inventory/Crafting/Trading/Network and KitGlyphs.Inventory/Crafting/Trading/Network become the plugin's own constants (e.g. InventoryPalette, InventoryGlyphs registering through KitGlyphs.Register). Every other glyph name is unchanged.
  • The style sheet is COREEditorKit.uss; EditorPrefs keys moved to EditorKit.* (language resets to English once, sidebar folds reset once).
  • textEdition.placeholder → KitInput.Placeholder(field, text).
