In-game console

CORE's own console (since v1.2): Assets/COREToolkit/Console, namespace CORE.Console. Drops down from the top edge of the screen, shows the Unity log (filters, search, collapse, stack traces) and runs commands declared with attributes. Drawn with IMGUI from a [RuntimeInitializeOnLoadMethod] host — no canvas, no EventSystem, no input package, no DI: it exists even when the game failed to boot. Opens with the toggle key (` by default) or, on mobile, a finger held at the top edge.

Game_Shared_AD, ModTool_AD and Examples_AD reference only ConsoleApi_AD. The module switch (Tools/CORE/Settings → Console → Console enabled) adds or removes CORE_CONSOLE_DISABLED on every build target: off, Console_AD is not compiled and ships nothing; the attributes stay in the code and ConsoleHub turns into a no-op (IsOpen false, Execute ignored). A project that prefers another console implements IConsoleBackend over it and calls ConsoleHub.SetBackend(...).

Declaring commands

using CORE.Console;
using UnityEngine.Scripting;
[Preserve, ConsoleCommandPrefix("player.")] // every name below becomes player.<name>
public static class PlayerCommands
{
[ConsoleCommand("heal", "Restores health"), Preserve]
public static void Heal(int amount = 100) { } // amount is optional: "player.heal" and "player.heal 50"
[ConsoleCommand("speed", "Movement multiplier"), Preserve]
public static float Speed { get; set; } = 1f; // two commands: "player.speed" reads, "player.speed 2" writes
[ConsoleCommand("tp"), ConsoleCommand("teleport"), Preserve] // aliases
[ConsoleDescription("Moves the player")]
public static void Teleport(Vector3 position) { }
[ConsoleCommand("wait", "Waits and reports"), Preserve]
public static async UniTask<string> Wait(float seconds) { ... } // awaited, result printed
}

  • Members must be static (instance commands bound to a MonoBehaviour are not supported in v1.2; an object can be registered explicitly with ConsoleHub.Register(obj) — its instance members with the attribute become commands bound to it, Unregister(obj) removes them).
  • [ConsoleCommand] without a name uses the member name. [ConsolePlatform(ConsolePlatform.Desktop | Editor)] limits where it loads (ConsolePlatform flags: Editor, Windows, Mac, Linux, Android, IOS, WebGL, Consoles, Desktop, Mobile, All).
  • Keep [UnityEngine.Scripting.Preserve] on the class and members — stripping is disabled in CORE builds, but mods and other projects may strip.
  • Overloads are told apart by argument count; two commands with the same name whose argument ranges overlap are refused (listed by the Setup Wizard check Console: commands and the Debugger page Console).
  • Return values: void prints nothing; a value is printed with ConsoleExecutor.Format (collections item by item, Unity objects by name); Task / Task<T> and UniTask / UniTask<T> (through CORE.Shared.Console.ConsoleUniTaskConverter) are awaited; IEnumerator runs as a coroutine. An exception inside a command is printed as an Exception line, never thrown out.

Argument types

Primitives, string, char, bool (1/0/true/false/on/off/yes/no), enums (Flag1|Flag2), Vector2/3/4, Vector2Int/3Int, Quaternion (3 Euler angles or 4 components), Color (#RRGGBB[AA], a Unity color name, r g b [a]), Color32, Type, T[] and List<T> of any of those ([1, 2, 3] or 1,2,3), Nullable<T> (null), GameObject and any Component by object name (GameObject.Find). A decimal comma is accepted.

Tokenizer: whitespace separates, "quotes" keep spaces, ( ) [ ] { } keep their content together, \ escapes, ; separates statements on one line.

Custom type: a class with [ConsoleParser] and a parameterless constructor implementing IConsoleParser<T> (bool TryParse(string text, out T value)); found on load together with the commands.

Where commands are found

On start every loaded assembly that references ConsoleApi_AD (or the legacy IngameDebugConsole.Runtime) is scanned on a worker thread (on WebGL, where there is none, synchronously) and committed on the main thread; help says "(still loading)" until done. Registering an assembly the start-up scan already covered is harmless — members already registered are skipped. A mod's assemblies are added by Mod.LoadResources (ConsoleHub.RegisterAssembly) and removed on unload. Game code may call ConsoleHub.RegisterAssembly(assembly) for anything loaded by hand.

ConsoleHub (game-facing API)

Member Use
IsInstalled, Backend whether any console is behind the hub
IsOpen, OpenChanged (Action<bool>, main thread) pause gameplay input or time while the window is open; CORE's InputSystem already restricts every input group while IsOpen, and the console disables the scene's uGUI EventSystem (found by name, no reference) so clicks on the window do not reach the game's UI. Two consequences for game code: EventSystem.current is null while the console is open, so a per-frame "pointer over UI" check must treat no EventSystem as "over UI" (or skip); and input read outside CORE's InputSystem (Keyboard.current, legacy Input) still reaches the game while the player types — gate it on IsOpen / OpenChanged
Open(), Close(), Toggle() from a pause menu button, a gesture
Execute(line) run a line as if typed (echoed as a Command line)
Print(text, ConsoleMessageType) a console-only line, bypassing the Unity log (Success, Result, …)
RegisterAssembly / UnregisterAssembly, Register(object) / Unregister(object) commands loaded at run time; calls made before the backend exists are replayed into it
AddResultConverter(IConsoleResultConverter) teach the executor another awaitable or result type; one converter per type, registering again is ignored
SetBackend(IConsoleBackend) plug another console

The Console page of the examples scene (Examples/Scripts/ConsoleExample.cs) does all of this from buttons.

ConsoleMessageType: Log, Warning, Error, Exception, Assert (the Unity log types) plus Command, Result, Success. Filters in the window: Log = Log/Command/Result/Success, Warn, Err = Error/Exception/Assert.

Built-in commands

help (one line per command), help <name> (the overloads), help <prefix> (a group: help example), clear, echo <words…> (a params string[] command: the trailing arguments fill it — any command may end with params T[], ConsoleCommand.IsVariadic), history, history.clear, quit; groups that can be turned off in the settings: time.scale/fps/vsync/pause/info, scene.load/add/unload/restart/list (plain SceneManager, not CORE's SceneLoader — turn the group off if the game must go through its own loader), prefs.int/float/string/ delete/clear, logs.save [file]/count/test (file is a bare name under SaveFolder; a path is refused). CORE adds Common.SetPause and the Player.* Steam inventory commands (Scripts/Shared/Console/).

Window keys: Tab completes the name (repeated Tab cycles every match of what was typed, any other key resets), ↑ / ↓ history, Enter runs, Esc clears the line then closes; the toggle key closes too. The bottom strip drags the height (kept in PlayerPrefs).

Settings

ConsoleSettings (Console/Runtime/Settings) is a ScriptableObject. CORE's defaults ship in the package as Assets/COREToolkit/Resources/CoreConsoleDefaults.asset (ConsoleSettings.DefaultsName); a game that wants its own values presses Create under Project override in Tools/CORE/Settings → Console — a copy at Assets/Resources/CoreConsoleSettings.asset (ConsoleSettings.AssetName, the game's folder) that the console loads instead of the defaults and a package update never touches. ConsoleSettings.Instance = the override, else the defaults, else a fresh instance. The settings section edits whichever is active (Settings asset names it; Reset puts the override back to the defaults, the defaults back to the class values; Remove the override deletes it):

  • Module: AvailableInRelease (else editor + development builds only — Debug.isDebugBuild).
  • Opening: ToggleKey (KeyCode, read from IMGUI events), TouchHoldSeconds, OpenOnException, OpenOnStart.
  • Look: Scale × automatic scale (AutoScale: Off / Dpi / ScreenHeight against ReferenceHeight) — one number drives font, row height, buttons, markers and gaps (ConsoleMetrics); DefaultHeight / MinHeight / MaxHeight as a share of the screen; SlideSeconds; Theme (ConsoleTheme, a color per message type and for the window).
  • Log: MaxEntries, CollapseByDefault, TimestampsByDefault, HistorySize, SaveFolder (under persistentDataPath), ApplyStackTraces + a StackTraceLogType per log kind.
  • Built-in commands: TimeCommands, SceneCommands, PrefsCommands, LogCommands.

Editor side

  • Settings section Console (project scope) — module switch, the asset above, a button to the Debugger page, and at the bottom a Preview of the window drawn from the current values (1080p sizes, theme colors). The page follows the asset: edits in the Inspector, a created or deleted override rebuild it.
  • Debugger page Console — every command as the console loads it (signature column, description, source assembly in the tooltip, legacy badge), the refused members, in play mode the live registry, log counts, a Run line and on every command argument fields with a Run button.
  • Setup Wizard: Console: commands (refused members) and Console: [ConsoleCommand] (scripts still on the old attribute, scenes/prefabs still instancing the old prefab) — both optional.
  • Manual chapter Console.

Migration from IngameDebugConsole (until 1.4.0)

Assets/Plugins/IngameDebugConsole is a shim: the asmdefs and an [Obsolete] ConsoleMethodAttribute, every other script an empty stub (so an update leaves no duplicates), prefab and sprites gone. The new console reads [IngameDebugConsole.ConsoleMethod] by type name, so existing commands and built mods keep working; the rest of the old API is gone — DebugLogManager (→ ConsoleHub.Open / Close / IsOpen), DebugLogConsole.AddCommand / AddCommandInstance / RemoveCommand (→ ConsoleHub.Register(object) for instance commands, the attribute for static ones), [ConsoleCustomTypeParser] (→ [ConsoleParser] + IConsoleParser<T>), DebugLogEntry. Tools/CORE/Setup Wizard → Migrations → Console (also the wizard fix) rewrites the scripts bound to the old namespace: [ConsoleMethod( → [ConsoleCommand( — [ConsoleMethod("name", "description", "x", "y")] keeps compiling, the parameter names are a params string[] constructor of ConsoleCommandAttribute (ParameterNames, shown in help) — using IngameDebugConsole; → using CORE.Console;, and a reference to ConsoleApi_AD in the script's assembly definition (Assembly-CSharp has it through autoReferenced). A script that also uses the removed API keeps its old using and is listed with the replacements. Remove any instance of the old IngameDebugConsole prefab from scenes and prefabs by hand — ProjectContext.prefab no longer carries one. LegacyConsole.RemovedIn = 1.4.0.
