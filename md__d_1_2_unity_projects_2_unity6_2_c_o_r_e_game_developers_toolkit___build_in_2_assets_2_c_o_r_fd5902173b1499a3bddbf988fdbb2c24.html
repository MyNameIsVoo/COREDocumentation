Gamepad support (since v1.3)

Input modes and device detection, UI navigation by layers, groups and elements, prompts and button icons, a virtual cursor, haptics, rebinding, Steam Deck readability, local multiplayer, debugging and the editor tooling — on top of CORE.Shared.Inputs.InputSystem, which keeps its API (see systems.md for actions, providers and polling). Everything starts from InputHost, injected.

Quick start: a menu a gamepad can drive

  1. Settings. Tools/CORE/Settings → Input → Create the game's settings writes Assets/Resources/CoreInputSettings (the package defaults are overwritten by an update). The rest is edited in Tools/CORE/Input Editor.
  2. A panel = a layer. Put UIInputLayer on the panel's root (Add Component → CORE/Input/UI Input Layer, AutoActivate on): it enters the navigation stack when enabled in the Gamepad mode and leaves when disabled. The top layer is chosen by canvas sorting order and hierarchy.
  3. Rows = groups. UIInputGroup on each container of buttons (NavigationMode: LinearVertical, LinearHorizontal, Grid), linked to the next groups by Left/Right/Up/DownGroup or reached by moving off the edge.
  4. Buttons = elements. UIInputElement next to each Selectable (a CustomButton, a CustomToggle); a CustomDropdown also gets UIInputDropdownNavigation (its list becomes a nested layer); sliders, tabs, scroll views and cycles have widgets of their own (below).
  5. Back. The layer raises BackRequested on Cancel — the game closes its window there; a layer never closes itself.
  6. Prompts. UIInputButton (a shortcut on a Selectable), UIInputIcon / UIInputStandaloneIcon (the icon of an action for the current gamepad family), hints of layers, groups and elements highlighted with the focus. Ready prefabs in Assets/COREToolkit/Content/Prefabs/Input/: UI_InputSelectionFramePrefab (put it inside an element — its UIInputElementHint shows the frame (with the A prompt) while the element is focused) and UI_InputIconPrefab (a UIInputIcon with an image and a label; set its InputButton or InputAction). CORE's defaults already carry icons of Xbox, PlayStation, Steam Deck and any gamepad for the UI / VirtualCursor actions and all gamepad controls, and the cursor sprite.
  7. See it work. The demo scene's Gamepad page (Examples/Scripts/GamepadExample.cs, a page of UI_ExampleUICanvasPrefab) is a hub of eight windows (Examples/Scripts/Gamepad/) — navigation, groups and restrictions (a layer with nothing selected, activation buttons, the switch policies, IUIInputRestrictions), widgets, nested layers (two levels deep, a locked panel, a dialog pushed from code, a Visual hidden by B), tabs and lists, prompts, device and vibration (with the Steam Deck adapters), local players; each window is a layer that B closes. Every public scene component of CORE.Shared.Inputs is used there — look it up by name in the prefab.
  8. Check. The Setup Wizard's input checks and the inspectors of the layer, group and button point at what is missing; Tools/CORE/Debugger → Input shows the stack, the focus and the last events in play mode.
[Zenject.Inject] private InputHost _input;
_input.WhenInitialized(() =>
{
_input.InputModeChanged += mode => _hints.SetActive(mode == InputMode.Gamepad);
_input.Haptics.Play(0.4f, 0.8f, 0.15f); // low, high, seconds
});
myLayer.BackRequested += _ => CloseWindow(); // the layer asks, the game closes

Reference

  • InputGamepadSettings (CORE.Shared.Inputs) — a ScriptableObject with the settings of every gamepad feature: DefaultInputMode, AutoSwitchInputMode, GamepadFamilies (ordered keyword lists, first match wins, else Generic), the use thresholds (GamepadStickThreshold, MouseDeltaThreshold, TriggerThreshold), and the sub-settings Cursor (InputCursorSettings), VirtualCursor (VirtualCursorSettings), Navigation (InputNavigationSettings), Haptics (InputHapticsSettings), SteamDeck (SteamDeckSettings), ActionIcons (InputActionIconSet[]) and ControlIcons (InputControlIcon[]). InputGamepadSettings.Load() returns the game's Resources/CoreInputSettings, else CORE's Resources/CoreInputDefaults (a package update may overwrite it; a warning in the editor and development builds says to create the override), else a fresh instance. The override is created in Tools/CORE/Settings → Input. InputActionReference fields left empty fall back to CORE's UI and VirtualCursor maps by name — a game sets them only to use its own actions.
  • InputHost — bound in ProjectInstaller (NonLazy), inject it: [Zenject.Inject] private InputHost _input;. It builds the gamepad services in a fixed order once GameApplication.OnInitted fires and ticks them through GlobalUpdater on unscaled time (Time.unscaledDeltaTime): IsInitialized, IsDisposed, Settings, Input (the InputSystem), events Initialized and Disposing (handlers are isolated — one that throws does not stop the others), WhenInitialized(callback) (runs now or after the Initialized handlers). Required services throw InvalidOperationException before initialization, optional ones are null. Scene components get it through [Zenject.Inject] + DiContainerRef.Container.Inject(this); there is no static facade.
  • Modes and devices (CORE.Shared.Inputs.Devices): InputHost.Mode is the InputModeService — CurrentMode (InputMode.KeyboardMouse / Gamepad, starts at Settings.DefaultInputMode), SetInputMode(mode) (raised on a change only), InputModeChanged. InputHost.Devices is the InputDeviceService — ActiveDevice, CurrentGamepadFamily (GamepadFamily.None while the active device is no gamepad), Classify(device), NotifyDeviceUsed(device), ActiveDeviceChanged, GamepadFamilyChanged. The host mirrors them as CurrentMode, CurrentDevice, CurrentGamepadFamily and the events InputModeChanged (raised after every host service reacted — subscribe here, not to the service), ActiveDeviceChanged, GamepadFamilyChanged. With Settings.AutoSwitchInputMode the mode follows the last meaningfully used device: the InputDeviceUseDetector listens to every triggered action of CORE's asset and the game copies (magnitude against GamepadStickThreshold / TriggerThreshold / MouseDeltaThreshold) and polls the current gamepad, keyboard and mouse every frame, so a device counts even with none of its maps enabled. Never counted: a mouse's absolute position (a warp), a non-native mouse (the virtual cursor), the mouse inside InputHost.SuppressMouseDeviceUsed(duration). When the active device is removed the service falls back to the current gamepad → any gamepad → the keyboard → the native mouse; nothing fits → the device stays.
  • Hardware cursor: InputHost.CursorControl (CursorControlService, null before initialization) hides and locks the cursor in the Gamepad mode by Settings.Cursor (ManageCursorForInputMode, GamepadLockMode, EnforceEveryFrame re-applies it every LateUpdate) and restores what the game had set when the mode goes back or the host is disposed; IsCursorBlocked. Code that shows the cursor itself in the Gamepad mode loses every frame — turn ManageCursorForInputMode off instead. CustomCursor is unaffected (it only swaps the image).
  • Icons and labels (CORE.Shared.Inputs.Prompts): InputHost.Icons is the InputIconService. TryResolve(action, family, out InputIconContent content) (also with an InputActionReference) gives the Sprite Icon and LocKey Label of the action for the family from Settings.ActionIcons — the entry of the family, else the Generic entry; the entry's label wins over the set's; false for GamepadFamily.None or an action without a set. GetBindingDisplay(action, bindingIndex) → InputBindingDisplay { Path, Text, Icon, IsEmpty }: the binding's effective (rebound) control path, its human-readable name (InputControlPath.ToHumanReadableString, Latin whatever the keyboard layout), and an icon — the Settings.ControlIcons entry of the path for the gamepad family (InputControlIcon.Family: the family's entry, else the one for any family — None, the default —, else the Generic one; its label, translated, replaces the text) or CORE's key sprite of the path's KeyCode in Settings.KeyIconSize; a composite header joins its parts with / (W/S/A/D) and has no path or icon. The action may be the asset's — it is translated to the runtime copy. GetControlDisplay(path) is the same for a bare control path. Both take the current gamepad's family (None with no gamepad yet); the overloads GetBindingDisplay(action, index, family) / GetControlDisplay(path, family) take one. InputLabel.Resolve(LocKey): a key in the tables → its translation, any other key → the key text itself (so a field may hold a ready text), empty → "".
  • UIInputStandaloneIcon (CORE/Input/UI Input Standalone Icon, IconImage): shows the icon of one action for the active family — Bind(InputAction), Bind(InputActionReference), Bind("UI", "Submit"), ClearBinding(), Refresh(); the image is disabled without an icon; follows GamepadFamilyChanged, ignores the input mode. For a HUD prompt or a tutorial text; the hints of the navigation are a later part.
  • InputSceneComponent — derive the gamepad scene components from it: Host (the InputHost, null until injected), OnAttach(host) / OnDetach(host) run balanced once the host is known and the component is enabled. Injection: the container that instantiates the prefab, else DiContainerRef.Container.Inject(this) in Awake, else container.Inject(component) later (tests) — base.Awake() / OnEnable / OnDisable must be called when overridden. The host may still be uninitialized in OnAttach — use host.WhenInitialized.
  • EventSystem and the input module (CORE.Shared.Inputs.Navigation): InputHost.UI is the UIInputService — EventSystem, InputModule (the InputSystemUIInputModule), SetSelected(go), ClearSelected(), RestoreSelection(), LastSelectedObject, IsModuleNavigationDetached. In the Gamepad mode (and while a module locks it) the module's move / submit / cancel references are set to null so CORE's navigation is the only thing moving the selection; they come back in Keyboard&Mouse and on dispose. Settings.Navigation.EventSystemPolicy: UseExisting (default; the ProjectContext prefab carries the EventSystem — modules are never added or removed) or CreateIfMissing (creates CoreInputEventSystem, DontDestroyOnLoad, when the scene has none). The service follows EventSystem.current only when the tracked one is destroyed or disabled; a working one is never replaced. Entering Gamepad with RestoreFocusForGamepad re-selects the focus target (else the last selection); ClearFocusForKeyboardMouse clears it on the way back. The module's moveRepeatDelay/Rate are set from the settings.
  • Contexts and scopes: InputHost.Contexts is the UINavigationContextHost — Primary, ForPlayer(index) (created on demand, not available until a player joins), Available, AvailabilityChanged, IsInputEnabled, Version. A UINavigationContext is a stable per-player handle: Index, IsPrimary, IsAvailable, Mode, GamepadFamily, GamepadInputGate, AccentColor, HighlightSelectable, ResolveAction(reference | map, action), events ModeChanged (raised after the host's InputModeChanged handlers) and GamepadFamilyChanged; its services (navigation, hints, …) come with the later parts. Routing: Contexts.Resolve(component) returns the context of the nearest enabled UINavigationScope on or above the component, else Primary — and returns Primary at once, without walking, while no scope is alive (the single-player path). Components keep a UINavigationScopeCache field and call Resolve(this, ref cache); the cache is valid while Version is unchanged and the component is still under the cached scope; cache.Invalidate() in OnTransformParentChanged; Contexts.InvalidateCaches() after reparenting an ancestor of a subtree (Unity tells only the moved object). Components that depend on their context implement IUINavigationContextListener.OnNavigationContextChanged() (idempotent, cheap: re-resolve, move subscriptions) and register with Contexts.AddListener in OnEnable / RemoveListener in OnDisable — notified when a scope is created, enabled, disabled on a live panel, reparented, or its player changes; a panel deactivated as a whole does not notify. UINavigationScope (CORE/Input/UI Navigation Scope, PlayerIndex, SetPlayerIndex, SetContext(context), Context) goes on the layer's object or above it, never inside a layer. UINavigationContextHost.FindScope(component) is the honest walk for editor code.
  • The activation gate: InputHost.GamepadInputGate (GamepadInputActivationGate, null before initialization) — IsInputAllowed is false from the moment the Gamepad mode is entered (or a gamepad becomes the active device before the mode switches) until the sticks and the D-pad of the gamepad and the navigate action are neutral (AxisDeadzone, GamepadStickThreshold); without a navigate action it releases after RepeatDelay. The tick that armed it never releases it. Every navigation provider, button and widget checks it; game code that reads the UI actions directly should too, else the stick that opened a menu moves through it. Off with SuppressInputOnGamepadEnter = false.
  • UI navigation — the components (CORE.Shared.Inputs.Navigation, Add Component → CORE/Input/…). A screen gets a UIInputLayer on its root (AutoActivate on: it enters the stack when enabled in the Gamepad mode and leaves when disabled; off: the game calls Push() / Remove()); AllowEmptyGroup lets the layer have no active group ("nothing selected" until a group's ActivationAction), RememberLastFocus, DefaultGroup, Groups (collected from the children when AutoCollectGroups), RebuildOnEnable, RebuildOnChildrenChanged, MarkDirty() (rebuild in the next LateUpdate), Rebuild(), BackRequested (Action<UIInputLayer>): the layer never closes anything — the window subscribes and hides itself, or add UIInputLayerBackHidesVisual next to the layer to hide the parent Visual. Put a UINavigationScope on the layer's object or above it, never inside. Under the layer, UIInputGroup per list / grid / ring: NavigationMode (LinearVertical, LinearHorizontal, Grid, Radial), GridScoring (AxisAligned keeps the row, Nearest is Unity's rule), SwitchPolicy + LeftGroup / RightGroup / UpGroup / DownGroup (OnEdgeOnly hands over when the move runs off the edge, AlwaysByDirection whenever a neighbour is linked, ManualOnly never), DefaultElement (a grid prefers the lowest Priority), RememberLastElement, IsNavigationEnabled, AllowExternalNavigation, ActivationAction / ExitAction (InputActionReference), Activated / Deactivated (UnityEvents), IsActive, IsAvailable(). On each Selectable, a UIInputElement (UIInputElementBase to derive: RequiresSelectable, IsCustomAvailable(), OnFocusChanged): PriorityValue (lower first), SelectableReference / GroupReference (found in the parents when empty — a missing group or Selectable throws in Awake), IsNavigationEnabled / SetNavigationEnabled, AllowInputSubmit, Selected / Deselected, IsFocused, SubmitFromCode(), NotifyAvailabilityChanged() after anything that changes IsAvailable(): the component enabled on an active object, the Selectable enabled and interactable, every CanvasGroup above interactable (up to one with ignoreParentGroups), every IUIInputElementAvailability on the object must agree, and the host's Restrictions. Elements are ordered by Priority, then by the full hierarchy order; UINavigationMap.Build writes the Selectables' explicit Unity navigation to match, FindGridElement is the grid search.
  • UI navigation — the service: InputHost.Navigation is the primary's IUINavigationService (UINavigationService); a player's is context.Navigation. Layers (the stack), ActiveLayer (the top by canvas sortingOrder, then hierarchy — not the last pushed), ActiveGroup, ActiveElement, IsLocked, LastBackConsumedFrame; PushLayer / PopLayer / RemoveLayer / ClearLayers / IsInStack, SetActiveLayer / SetActiveGroup / SetActiveElement, Move(Vector2 | direction), Submit(), SubmitElement(e) (the submit handler on the focus target), Cancel(), Lock(bool), RebuildLayer / RebuildActiveLayer / MarkDirty(layer) (deferred, merged, flushed in LateUpdate before the focus is validated — spawning a table costs one rebuild), ValidateFocus() / HasValidFocus(), PresentFocus(go). Events: ActiveLayerChanged, ActiveGroupChanged (the groups' Activated / Deactivated fire first), ActiveElementChanged (the element's NotifyFocusChanged(true) fired first — IsFocused is already set; raised on a real change only — setting the same element again or keeping an empty focus raises nothing; a destroyed element reads as a null ActiveElement), NavigationMapRebuilt, FocusLost, FocusRestored, BackRequested(layer) (after the layer's own; null layer = no stack), LockChanged. Rules: Gamepad mode only — the layers are released in Keyboard&Mouse (their remembered focus is kept, the EventSystem selection is left to ClearFocusForKeyboardMouse; a game's own ClearLayers() still wipes both), the enabled AutoActivate layers of the context come back on entry; a layer that is disabled or destroyed without Remove() stops holding the focus (Contexts.EnabledLayers is the registry, no scene search); a layer lies in exactly one stack (StackOwner); Cancel first raises the layer's BackRequested, and when the stack changed because of it the press is consumed for that frame (a close button on the same physical control must not fire too); the lock is the game's Lock(true) or the system's (console open, InputGroups.UI restricted — IsLocked covers both — the gamepad's Cancel is ignored too, RequestBack() from code is not); IUIInputRestrictions (host.SetRestrictions) vetoes elements but the focus is only rechecked on ValidateFocus(). The primary's focus is the EventSystem selection, put back on the focus target in every LateUpdate; a player's focus is shown through ISelectHandler / IDeselectHandler (never the EventSystem) and re-selected once when the EventSystem selection leaves it. host.AreGamepadPromptsActive / context.AreGamepadPromptsActive = available and not locked: the one gate for prompts, button presses and group activation.
  • UI navigation — the input: host.NavigationInput (UINavigationInputProvider, Enable / Disable, Tick(dt), SuppressHeldDirection(), NavigateAction / SubmitAction / CancelAction) reads Settings.Navigation.NavigateAction / SubmitAction / CancelAction, each falling back to CORE's UI/Navigate / UI/Submit / UI/Cancel: per-axis deadzone (AxisDeadzone), hysteresis (a held direction keeps winning a diagonal), repeat (RepeatDelay, then RepeatRate), submit and cancel on performed. In the Gamepad mode it enables the actions' map through InputSystem.RegisterProvider(mapName) (so the console / a restricted group still silence it) and the three actions (only the ones it enabled are disabled on the way out). It never moves while GamepadInputGate.IsInputAllowed is false. host.GroupSelectionInput (UIGroupSelectionInputProvider) follows the active layer: a group's ActivationAction enters it from the empty state, its ExitAction leaves a layer that CanHaveEmptyGroup; after either, the held direction is suppressed so the next tick does not move the focus that was just placed. Both providers are enabled by Contexts.EnableInput() when Settings.Navigation.EnableUINavigation.
  • Shortcut buttons: UIInputButton (CORE.Shared.Inputs.Prompts, CORE/Input/UI Input Button, needs a Selectable) — a button pressed by a gamepad action outside the focus: InputAction (reference), PressDuration (> 0 = hold-to-press with HoldProgressFill, an Image set to Filled), PressTrigger (ButtonDown / ButtonUp, plain presses only), InvokeSelectableSubmit (Submit → a Button's onClick), Pressed (UnityEvent). When it is live (IsInputAvailable): IsBindingActive (SetBindingActive(false) from code switches it off), AttachedLayers (live only while one is the context's active layer, in the Gamepad mode), AttachedElements (one of them focused), HideWhenAnyElementFocused. Visibility is a separate predicate (AreVisualsAllowed): HideWhenBindingInactive and HideWhenSelectableDisabled switch VisibilityRoot (the button's own object when empty; the Selectable rule refuses a root that is the button or its parent — it would hide itself for good). A button that hid itself stays registered and comes back by itself; events BindingActiveChanged, InputAvailabilityChanged (on a real change only — the icons re-resolve on it). CanPress() = prompts live, Restrictions.IsButtonPressAllowed, live, active, interactable, CanvasGroup chain. Every press shows on the Selectable (SetPressedVisual, through the pointer down / up handlers): pressed from the gamepad button's press to its release — plain, hold and release triggers alike. Pressed by host.UIBindings / context.UIBindings (UIInputBindingService, Register / Unregister, Tick(dt)): one subscription per action, hold timers (an early release cancels), armed releases; silent outside the Gamepad mode, behind the gate, while prompts are off, and for the press a navigation Back consumed this frame on the cancel action or any action on the same physical control (cancel.controls) — the close button on the east button does not fire together with Back. An action is disabled on the way out only when the service enabled it.
  • Hints (UIInputHintBase, IUIInputHint): Targets (switched on while highlighted; empty — the hint's own object, so a hint is hidden until the focus reaches it), Icons (collected from below when empty, AutoCollectIcons), TintGraphics (the player's AccentColor, authored colors restored), IsHighlighted, SetHighlighted, CanShowIcons (virtual), ResolveNavigationContext() (virtual: the nearest scope; a group hint goes through its group). UIInputLayerHint (layer.Hint, found below when empty), UIInputElementHint (element.Hint / HintReference), UIInputGroupHint (group.Hints, collected from below when empty; may lie outside the group — the group calls SetGroup; RequiredElements / RequiredGroups / RequiredTransformActiveChildren: shown only while any is available; HasActivationAction = the group has an ActivationAction — then the hint is the prompt to enter the group, shown only while the layer has no active group, and its first icon shows the activation action). host.Hints / context.Hints (UIInputHintService): highlights the active layer's, element's and group's hints (a group's activation prompts only in the no-group state), SetVisible(false) hides everything and turns AreGamepadPromptsActive off (cutscenes), AreVisible, VisibilityChanged, Refresh(); every LateUpdate in the Gamepad mode it checks the activation prompts for drift (a group's availability changes without an event) and refreshes once. Gamepad mode only.
  • UIInputIcon (CORE/Input/UI Input Icon): IconImage, Contents (switched with the icon), the action — InputButton's, else the one a hint set (SetInputAction), else InputAction; Hint (found in the parents when empty), LabelText (a TextComponent — the font follows the language) with CustomLabel (a LocKey or a ready text) over the action's label; Refresh(), Clear(), IsShowing, CanShowContent (the context's prompts live, InputButton.AreVisualsAllowed, Hint.CanShowIcons). Shows the family icon from host.Icons; follows the mode, the family, the lock, the hints' visibility, the button's events and LocalizationManager.OnLanguageChanged. Its context: the hint's, else the button's, else its own scope. Unlike UIInputStandaloneIcon it depends on the prompts being live.
  • Dropdowns: UIInputDropdownNavigation (CORE/Input/UI Input Dropdown Navigation, needs a CustomDropdown) next to the dropdown's UIInputElement. Submit opens the list (the dropdown's own OnSubmit); in the Gamepad mode the open list gets a UIInputLayer (AutoActivate off), a vertical UIInputGroup on the items' parent and a UIInputElement on every item's toggle, built at run time from CustomDropdown.ListShown / ListItems, and is pushed into the dropdown's context (ListLayer) with the selected item focused; ItemHint (a prefab with an UIInputElementHintBase, e.g. UI_InputSelectionFramePrefab) is instantiated on every item so the focus shows. Submit on an item picks it and the dropdown hides; Back (the layer's BackRequested) hides it; ListHidden removes the layer and the focus returns to the dropdown. Keyboard and mouse: nothing changes.
  • Element variants (CORE.Shared.Inputs.Widgets, all derive from UIInputElementBase): UIInputEmptyElement (RequiresSelectable false, focus target = its object, ISubmitHandler: Submit toggles Submitted / SubmitCanceled, IsSubmitted, CancelSubmit(); losing the focus cancels — tooltips); UIInputSliderElement (Slider found on the object or above, LeftAction / RightAction → UI/DPadLeft / UI/DPadRight by default, StepPercent, HoldMoveSpeedPercentPerSecond, ApplyStepOnPress; moves only while it is the context's ActiveElement, the gate is open and the prompts are live; the wrapper Selectable, if any, gets Navigation.Mode.None; it owns its axis — IUIInputDirectionHandler.HandleDirection: the navigation offers it every move first, along the slider it steps the value (the stick with the navigation's repeat; a held own action moves it in Update instead) and the focus stays, across it the focus moves on — implement the interface on an element of your own that uses a direction); UIInputDualButtonElement (Primary / Secondary UIInputButtons: HideWhenBindingInactive forced on, the bindings active only while this element is the focus in the Gamepad mode — one pair of actions for every row; no Selectable, no focus target); UIInputNestedLayerElement (TargetLayer found below, must not AutoActivate; ISubmitHandler → EnterLayer() when CanEnter() — the nested layer has a focusable group — else retried one frame later because the same Submit may be building the content; the nested layer's BackRequested → ExitLayer(): Remove, focus back on the element, Exited; TryAutoExitEmptyLayer every LateUpdate; disabling removes the layer; Entered / Exited, IsEntered). UIInputNestedLayerBackRequester is the exit half alone for a layer the game pushes; UIInputNestedLayerElementHint (AlwaysShowIcons) hides its icons while CanEnter() is false. IUIInputRestrictions also has IsButtonPressAllowed(button) and IsCyclingAllowed(controller).
  • Widgets: UIInputTabController (Layer found above, Tabs of UIInputTabEntry { TabButton, ContentGroup, HideOnGamepad }, PreviousTabButton / NextTabButton (shortcut buttons, their Submit turned off), DefaultTabIndex, HideInactiveContentGroups, WireTabButtonClicks; ActiveTabIndex, TabCount, SelectTab(i), SelectNextTab() / SelectPreviousTab() (skip unavailable tabs), IsTabAvailable(i), ActiveTabChanged): the active content group is enabled, rebuilt and made the active group when the layer is active in the Gamepad mode, the tab buttons get the select/deselect handlers, mouse-only tabs are deactivated on the gamepad; state is applied after the frame's LateUpdates (UniTask.Yield(LastPostLateUpdate)) because the host restores the focus in LateUpdate; moving the focus into another tab's content group selects that tab. UIInputCycleController (TargetLayer / TargetLayers — active while any is the active layer, always without; PreviousItemAction / NextItemAction → UI/LeftShoulder / UI/RightShoulder, WrapAround, SubmitSelectedItemOnTransition, RememberLastSelection, SubmitSelectedItemOnInitialize; SelectedItem, Items, Select(item, submit), SelectNext() / SelectPrevious(), CanCycle(), SelectedItemChanged) with UIInputCycleItems below it (registered in OnEnable, ordered by sibling index, available while active and interactable, selected by a click too, InvokeSelection() = a Button's onClick or the submit handler) and UIInputCycleItemHint (icons [0] previous, [1] next; highlighted on the selected item only, re-checked every LateUpdate). UIInputScrollController on a ScrollRect (ScrollAction → UI/Scroll, Vertical / Horizontal, ScrollSpeed px/s, TargetLayer, UIInputScrollHint with FirstIconAction / SecondIconAction): the stick scrolls in LateUpdate while CanScroll(), inertia cleared on input. UIInputScrollIntoView on a ScrollRect (ScopeGroup, ScopeLayer found above, ViewportPadding, ScrollVertical / ScrollHorizontal, ScrollDuration 0 = instant): queues the focus target on every focus change and map rebuild of the scope layer, scrolls in LateUpdate after a forced layout pass, on unscaled time.
  • The selection frame: shader CORE/UI/InputFrame (Assets/COREToolkit/Content/Shaders/UIInputFrame.shader — a solid rounded line, anti-aliased; _Thickness, _CornerRadius, _RectSize) on an Image with UIInputFrameRectSize (writes the rect coordinates into uv0.zw and _RectSize into a material instance, so the line keeps its width whatever the sprite, the Image type or the frame's size), UIFrameTargetFitter (Target, Padding, Fit() every LateUpdate, works across hierarchy branches; off in the prefab — switch it on and set Target when the frame lives outside the element). CORE ships the material Content/Materials/UI/UI_InputFrame.mat and the prefab Content/Prefabs/Input/UI_InputSelectionFramePrefab (a stretched root with UIInputElementHint, Targets = the Frame child 8 px outside the element, TintGraphics = its image; a UI_InputIconPrefab on UI/Submit anchored to the frame's bottom-right corner shows the A prompt). Both prefabs are built of CORE's UI — nested CustomImagePrefab / CustomTextPrefab, never Unity's bare Image / TextMeshProUGUI; build your own prompts and frames the same way (IconImage / HoldProgressFill take the CustomImage). A cycle item's frame is the same image under a UIInputCycleItemHint (the demo's difficulty switch).
  • The virtual cursor (InputHost.VirtualCursor, VirtualCursorService, CORE.Shared.Inputs.VirtualCursors, settings InputGamepadSettings.VirtualCursor): a stick-driven cursor for screens built for the mouse (a map, a board, drag-and-drop). It is a real virtual Mouse device named VirtualCursorMouse (VirtualMouse while active): its position and left button are written every tick with InputState.Change, it is Mouse.current while the cursor is active, so the InputSystemUIInputModule hovers and clicks through it like through any mouse and InputPointer / CustomCursor read it without changes; the device-use detector ignores it (native == false). Enable() / Disable() / SetEnabled only request the cursor (IsRequestedEnabled): it is active (IsEnabled, EnabledChanged) while the mode is in AllowedInputModes (default Gamepad; empty = any) and deactivates by itself on a mode change, coming back when the mode allows again. EnabledOnStart, VisibleOnStart; Show() / Hide() hide only the image (IsVisible, VisibilityChanged). Movement: MovementAction (default VirtualCursor/Move, left stick) through Deadzone (rescaled 0..1) × Speed px/s on unscaled time, clamped to the screen; SetSpeedShaper(Func<float,float>) reshapes the magnitude (an ease-in for precision); Pin(Func<Vector2>) / Unpin() / IsPinned glue the cursor to a moving target (a dragged card) — the stick and the magnets are ignored, the target is re-read in LateUpdate so it never lags a frame. Click: SubmitAction (default VirtualCursor/Submit, south button) presses the virtual mouse's left button (SimulateMouseClick, IsPressed); the press that activated the cursor (the submit that closed the layer covering it) is swallowed; disabling while pressed releases. IncludeUIMouseClick additionally sends simulated pointer enter/exit/down/up/click/drag to the UI under the cursor (VirtualPointerSimulator) — for a scene whose EventSystem has no module following the mouse; with the module it would double the click, keep it off there. Position / SetPosition(screen) / MouseInput (the cursor while active, else the hardware mouse). Sprites: DefaultSprite, CursorSize, Pivot, named Sprites (VirtualCursorSpriteEntry: Id, Sprite, Size 0 = shared, OverridePivot; CORE's defaults: an arrow with the hot spot at the tip, and Ring — a ring with a dot, the hot spot in the middle) — SetSprite(sprite), SetSpriteById(id) (unknown → default, false), ResetSprite(). The image is VirtualCursorView (View) on an Overlay canvas of SortingOrder (short.MaxValue), built in code under a DontDestroyOnLoad root, or instantiated from CanvasPrefab (the component on the root or a child, CursorImage wired; through DI); SetColor tints it. Going away: a held press is cancelled (pointer up and end drag, never a click or a drop), the hardware mouse — unless Cursor.lockState is Locked, which is never touched — is warped to the cursor's position (WarpCursorPosition + a state change with zero delta, inside SuppressMouseDeviceUsed, so the warp never flips the mode), made current again, and the virtual device is removed in onAfterUpdate — never inside an action callback, where removing a device loses the frame's remaining events, and unpaired from its user first, so no DeviceLost is raised for it; a re-activation before that update reclaims the same device. The VirtualCursor map is enabled through CORE's provider (RegisterProvider("VirtualCursor")) on activation, so the console and restricted groups still silence it. A custom CanvasPrefab never takes raycasts (its image, raycasters and a CanvasGroup are switched off for it); a player cursor's press keeps the EventSystem selection.

  • Local multiplayer (InputHost.Players, PlayerService, CORE.Shared.Inputs.Players): up to InputGamepadSettings.Players.MaxPlayers players (the primary included), each on a gamepad of its own; keyboard and mouse always belong to the primary. While the primary plays alone nothing of this exists — no InputUser, no copies of the assets, the host routes devices as before (IsSinglePath). Join(gamepad) returns the PlayerSlot of the lowest free index (null, with a warning, when the gamepad is a player's already, the primary's own, or every slot is taken — CanJoin(gamepad, out reason) tells first); if the primary played on that very gamepad without a pairing, the gamepad goes to the new player and the primary falls back to the keyboard or the native mouse. Leave(slot) frees it. Both are queued to the next tick when called inside an input update (an action callback, a UI button pressed by the gamepad): the slot comes back at once, IsJoined and PlayerJoined come next tick. EnableJoining() opens a lobby — the primary gets paired, the UGUI module loses move/submit/cancel, and with PlayerJoinPolicy.AnyButtonOnUnpairedGamepad any real button (not a stick, not a synthetic control) on a gamepad nobody plays on joins it; DisableJoining() closes it. A gamepad that left with a button still held gets a cooldown until it is neutral — releasing a hold-to-leave button must not join it back; an explicit Join lifts it. GetSlot(i) (0..MaxPlayers − 1, throws outside), Primary, Joined (the primary first), JoinedOthersCount, IsFull, FindByDevice(device), events PlayerJoined / PlayerLeft / JoiningChanged. A PlayerSlot is a stable object per index — subscribe once, it survives leaving and joining: Index, IsPrimary, IsJoined, IsPaired, User, Devices, PairedGamepad, ActiveDevice, Mode (players 1..N are always in Gamepad), GamepadFamily, NavigationContext (= Contexts.ForPlayer(i) — put a UINavigationScope with that PlayerIndex on the player's panel; a join without any layer resolving to the player logs a warning), Haptics (the player's own service: vibrates its gamepad only, follows the primary's enabled/intensity), VirtualCursor, Actions (the player's runtime copy of CORE's asset, same action ids; ResolveAction resolves a reference into the copies), EnableMap / DisableMap / ReleaseMap (a player's maps mirror the primary's enabled maps — the console and restricted groups included — unless chosen explicitly; ReleaseMap goes back to mirroring), events ModeChanged / DeviceChanged / GamepadFamilyChanged (the primary's forward to the host's), DevicesChanged, DeviceLost (the gamepad went: the slot stays joined, the game decides whether to Leave), DeviceRegained. Binding overrides of the copies follow the primary's on every BindingsChanged — rebinding is the primary's only.
