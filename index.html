Resource Manager

Resource Manager is a powerful tool that provides convenient loading and unloading of prefabs, scenes, images and other resources of your project. It supports working with Asset Bundles and Streaming Assets folder, which allows you to effectively manage resources in the game. With Resource Manager, you get fast and convenient access to project files through code, which greatly simplifies the development process. This tool tightly integrates with Code Generator and Mods Support, allowing developers to easily add new features and content to their games. The main functions of Resource Manager include:

  • Loading and unloading of various types of resources (prefabs, scenes, images, etc.).
  • Support for Asset Bundles for effective resource management.
  • Working with Streaming Assets folder to store and load data available at runtime.
  • Convenient access to resources through code for quick interaction.
  • Integration with Code Generator and Mods Support for extensibility of functionality.

Let's figure out which fields are responsible for what:

Resource Datas - All internal resources that do not follow the general rules of code generation, such as Localization keys, which must be consistent throughout the entire project. In essence, Resource Datas generates enumerations for each of the lists. To add your resource to the list, you must first write a rule by which the enumerations will be generated.

  1. Type - resource type (string) or its name, must be unique
  2. Paths - paths where the resources are located

Bundle Datas - a list of all bundles in the game that will be collected. There is no need to manually set the bundle to which each asset belongs. All assets that are inside the folder will be automatically included in the bundle!

  1. Name - the name of the bundle, must be unique
  2. Variant - the variant of the bundle, must be unique in the bundle
  3. Paths - the paths where the resources are located. It is enough to specify the root folder with the resources

Asset Datas - resources for which enumerations and data for accessing them via Asset Bundles should be generated

  1. Name - unique resource name
  2. Bundle - bundle to which the resource belongs
  3. Paths - paths where resources are located
  4. Name Regex - Works in conjunction with Enum Values, at the moment you can specify maximum 3 Regex values. Leave the field blank if you want the resource name to be taken in full. For example, you have resources with the names UI_Player_Bob.png, UI_Player_Tom.png, UI_Enemy_Bill.png and you want to divide them into groups and names, for this you need to write Regex, which will take the necessary strings from the name, in this case Regex will look like this "Name_(.+?)_(.+?)$". This means that we will take Player and Enemy from the name and create an enumeration with the name Group, then we will take Bob, Tom, Bill from the name and create an enumeration with the name Name. The example below shows that we take two parameters from the name and create enumerations from them. All the rules for constructing enumerations are specified in the Enum Values fields, where each list element corresponds to one Regex value.
    For a more in-depth understanding, please check out Example.
  5. Type - resource type. For example, localization keys or sprites.
  6. Directory Save Path - path to generate resources. Leave the field empty if you want the resources to be generated in a common folder
  7. Enum Values - rules for constructing enumerations. It is important to remember that the Enum field has priority - if you specify both Name and Enum fields, then the Enum field will ultimately be taken as a more valid rule.
  • Name - any enumeration name, may not be unique, for example, size, value, name, etc.
  • Enum - any existing enumeration. for example, UnityEngine.KeyCode. It is important to specify the full path to this enumeration, with all Namespaces
  • To Upper - indicates that the enumeration should be written in uppercase Assets/COREToolkit/Scripts/Shared/Generated

Example of use:

// C#
// Load Visual from Bundles
ResourceComponent visualRC = ResourcesPlayerGenerated.LoadGameObjectExamples(new EnumData<ResourcesPlayerGenerated.ExamplesGameObjects>(ResourcesPlayerGenerated.ExamplesGameObjects.UI_ExampleGameObject, null), RootSpawnGameObject);
// Unload Visual from Memory
ResourcesPlayerGenerated.UnloadSpriteExamples(ResourcesPlayerGenerated.ExamplesSprites.UI_ExampleIcon_0);

Mods Support

Mods Support is a powerful tool that simplifies the process of generating and packaging mods for your game. It allows developers or users to easily create and integrate custom modifications, which greatly expands the possibilities of the gameplay and increases replayability. The main features of Mods Support include:

  • Convenient mod generation: The tool allows you to quickly create and pack mods, which can then be easily integrated into the game.
  • Project assembly: Based on the use of Assembly Definition and Asset Bundles, which ensures reliable and efficient operation of mods.
  • Export window for modders: A special interface for exporting mods that simplifies the process of creating and managing custom content.
  • Setting code restrictions: The ability to set restrictions for code, which allows you to control the functionality of mods and prevent possible conflicts.
  • Additional materials: Developers can supply additional materials along with the tool, which makes the integration process more convenient.
  • Starting point for mods: The tool provides a single place to start and stop all mods, making them easier to manage.
  • Change tracking: The system tracks the addition and removal of mods from the Mods folder, ensuring that the content in the game is up to date.
  • Compatibility with the engine version: All mods must match the engine version used in the game, which guarantees stability and performance.

With Mods Support, you can easily extend the functionality of your game and give players the ability to create and share their own modifications. ModTool was taken as a basis and completely redesigned for its own needs.

Working with mods comes down to a few rules:

  • You need the CORE Mod tool
  • You need Documentation of your project

How to create your own mod

In order to create your own mod you need:

  1. Export the CoreModTool tool to an empty Unity project.
  2. After exporting the tool, open the Tools/ModTool/Export Mod window
  3. Enter the mod name
  4. Click the Prepare button and 2 files Boot.cs and **{ModName}_AD.asmdef** will be generated in your project

The structure of the Boot.cs file is:

// C#
using CORE.ModTool;
using CORE.ModTool.Tool.Mod;
using UnityEngine;
namespace ModExampleTestMod
{
public class Boot : ModHandler
{
private static Boot _instance;
// This is where the mod is initialized, we load it
[ModOnLoaded]
public static void ModOnLoaded(Mod mod)
{
if (mod == null)
{
Debug.Log($"The mod [{mod.Name}] has not been loaded!");
return;
}
_instance = Create<Boot>(mod);
Debug.Log($"The mod [{mod.Name}] has been loaded!");
}
// The mod is being unloaded here, all resources and memory must be freed
[ModOnUnloaded]
public static void ModOnUnloaded(Mod mod)
{
if (mod == null)
{
Debug.Log($"The mod [{mod.Name}] has not been unloaded correctly!");
return;
}
if (_instance != null && _instance.gameObject != null)
GameObject.Destroy(_instance.gameObject);
_instance = null;
Debug.Log($"The mod [{mod.Name}] has been unloaded!");
}
}
}

Config System

Config System is a powerful tool for managing game data that allows you to store and load all the necessary information in separate files with the .json extension. This provides convenience and flexibility in working with configurations, and also simplifies the process of editing and updating them. The main functions of Config System include:

  • Data storage in .json: All game data is stored in a convenient .json format, which makes it easier to edit and integrate.
  • Convenient loading of configs: Quick loading of configuration files is carried out simply by specifying the path to the file, which saves the developer's time.
  • Two types of configs: – Singleton: A configuration that is present in a single copy.
  • List: A configuration that can store multiple arrays of user data, which allows you to organize information more efficiently.
  • Nested configs: Configs can contain other configs inside themselves, which allows you to create complex data structures. Once deserialized, they can be accessed as full-fledged objects, not just strings.
  • Validation stage: All configs are checked for errors. If an error is found during validation, it will be displayed in the Unity console with an indication of the conflicting element, which simplifies debugging.
  • Flexible data storage: Configurations can store keys for other configs, localization, images and much more, which makes the system universal and multifunctional.
  • Convenience for game designers: Game designers will find it easy to work with configurations thanks to the intuitive .json format. They can quickly edit game parameters without having to interact with the code, which significantly speeds up the process of testing and adjusting game mechanics.

With Config System you can easily manage all aspects of your game data, keeping it flexible and editable. Configs are just a text file in .json format (or some other format, but Config System uses them). An example of what list configs might look like:

It is a static class that stores data about the player and other objects, such as the state of scene transitions, making it an indispensable tool for managing game data. The main functions of Model include:

  • Unified data system: Consolidates all session and player information, allowing access to data from any part of the game.

With Model you can efficiently manage player data and game state, ensuring a stable and continuous gameplay experience.

Hot to save?

It's very simple, inherit your data from the SaveGameBaseComponentData interface. Also you should have a manager class, inherit it from ISaveGameBaseComponent and subscribe to SaveComponentsManager, then specify what you will save and how to load the data, for example:

// C#
public class SavedDataClass : ISaveGameBaseComponent // This is the governing class
{
public class Data : SaveGameBaseComponentData // This is our data
{
public float SliderValue;
}
private readonly CustomSlider _slider;
[Zenject.Inject] protected SaveComponentsManager _saveComponentsManager;
public string ProgressMessage => "Example...";
public SavedDataClass(CustomSlider slider)
{
_slider = slider;
}
public void Init()
{
_saveComponentsManager.Add(this);
}
public SaveGameBaseComponentData CollectData() // Here we collect all the data to save
{
var data = new Data();
data.SliderValue = _slider.value;
return data;
}
public void LoadData(SaveGameBaseComponentData savedData) // Here we upload data
{
if (savedData is not Data data)
return;
_slider.SetValueWithoutNotify(data.SliderValue);
}
public void Destroy() // After deleting an object, we exclude it from the list of saved objects.
{
_saveComponentsManager.Remove(this);
}
}

After this, you can safely save and load data from the file. For a deeper understanding, study the examples.

Visual View Model

Visual View Model (VVM)** is a simplified version of the MVC pattern designed to make it easier to work with data in games. This approach is based on the principle of closed data handling, where all data is processed in the View, stored in the Model, and visualized using Visual components. The main features of the Visual View Model include:

  • Simplified architectural pattern: VVM offers a lighter and more accessible way to organize code compared to classic MVC, which makes it ideal for game developers.
  • Data closedness: All data is processed in the View component, which allows you to separate the presentation logic from the business logic and improve the manageability of the code.
  • Inheritance from the Visual component: All user interface (UI) elements must inherit from the Visual component, which ensures uniformity in handling events, such as the Update or Awake methods. This simplifies the management of events and interactions.
  • Flexible usage: VVM is not a strict rule, but rather a recommendation. Developers can choose to use VVM or their own system, allowing them to tailor the architecture to the specific needs of the project.
  • Developer-friendly: Thanks to the VVM structure, developers can integrate and test UI elements faster, which contributes to a more efficient development process.
  • Support for reactive programming: VVM can be easily adapted to work with reactive data, allowing the UI to update in real time when the model state changes.

With Visual View Model, you will get a powerful tool for organizing code and managing the UI in your games, which will make the development process easier and more intuitive.

Steam Inventory

A Powerful Toolkit for Managing In-Game Items

Integrating Steam Inventory into your Unity game unlocks immense potential: from granting items for achievements and selling cosmetics in the store to complex exchange and crafting systems. However, working with the low-level Steamworks API can be challenging and intricate.

The presented Steam Inventory system abstracts this complexity, providing a clean, powerful, and easy-to-use toolkit for the entire item lifecycle—from their creation in the Unity Editor to managing them in the live game.

Proven in Production: Powering Solunas Mood

This very system is not just theoretical—it's the backbone of the inventory and economy in the released game Solunas Mood. The game utilizes these tools to manage its entire catalog of items, handle player inventory synchronization, and drive its core progression loops, demonstrating the system's robustness and scalability in a commercial environment.

What is it for?

  • Declarative Item Creation: Define all your Steam items right inside the Unity Editor as configurable Scriptable Objects. Set names, descriptions, quality, tags, icons, and all required Steam properties in the inspector.
  • Automatic JSON Generation: The system automatically generates a SteamInventory.json file in the exact format required by Steamworks. You no longer need to manually edit JSON files or worry about syntax errors.
  • Full-Cycle Runtime Management: A ready-made manager for your game that handles:
    • Loading item definitions from Steam.
    • Synchronizing the player's inventory.
    • Granting items (both manually and via drops).
    • Exchanging and combining items (e.g., crafting).
    • Consuming items.
    • Tracking inventory changes in real-time through events.

How does it work? (General Architecture)

The system is built around several key components that work together:

  1. SteamInventoryBuilder (Editor Tool)
    This is your item designer. You create an asset via the CORE/SteamInventory menu and populate it with an array of items, configuring their properties. Clicking the Build JSON button validates all data (checks for unique IDs, correct relationships) and creates a file ready for upload to Steam.
  2. SteamInventoryManager (Runtime Core)
    This is the heart of the system in the built game. It:
    • Initializes on startup, loading all defined items from Steam.
    • Synchronizes the player's inventory, raising an OnChange event on any updates.
    • Provides methods for all core operations: GrantItemsToPlayer, ConsumeItem, ExchangeItems, TriggerDropRandomLoot, and more.
    • Operates asynchronously (using UniTask), ensuring it doesn't block the game's main thread.
  3. SteamItem and SteamPlayerItem (Data Models)
    These are the representations of your items.
    • SteamItem describes the item type (e.g., "Legendary Sword"), its static properties, and parses attributes from the Steam API into code-friendly structures.
    • SteamPlayerItem represents a specific instance of an item in a player's inventory (e.g., "That specific sword, and I have 2 of them"), tracking its quantity and state.

Basic Workflow Example

Step 1: Creating an Item in the Editor

  1. Create a SteamInventory asset via the CORE/SteamInventory menu.
  2. In the inspector, specify your game's App ID.
  3. In the Items array, create a new element. Assign it an ID, Name, Type, Quality, and other properties.
  4. Click Build JSON and upload the resulting file to the Item Store section in the Steamworks developer panel.

Step 2: Granting an Item to the Player in Code

// Get a reference to the manager
var steamInventoryManager = Core.Get<SteamInventoryManager>();
// Prepare an array of items to grant (e.g., by their ID)
SteamItemDef_t[] itemsToGrant = { (SteamItemDef_t)101, (SteamItemDef_t)102 };
uint[] quantities = { 1, 5 }; // Grant 1 of item ID101 and 5 of item ID102
// Asynchronously grant the items to the player
bool success = await steamInventoryManager.GrantItemsToPlayer(itemsToGrant, quantities);
if (success)
{
Debug.Log("Items successfully granted!");
}

Step 3: Reacting to a New Item
Subscribe to the manager's OnItemAdded event to react instantly to inventory updates (e.g., show a receive animation or update the UI).

steamInventoryManager.OnItemAdded += (newItems) =>
{
foreach (var item in newItems)
{
Debug.Log($"Received a new item: {item.Item.Attributes[Name].ValueString}");
}

  • The state machine editor now displays the name of the target object.
  • StateMachineAttribute now supports both Enum and bool types.
  • Added validation for tab elements in TabsItemData.
  • Added the ConfigVisual class for working with configs and mods, allowing modmakers to load resources based on common rules.
  • Added the SetMaskableWithoutRecursively method to IMaskableHelper for recursively setting the Maskable flag (use with caution, not in Update!).
  • Improved file name generation in CodeGeneratorHelper to prevent duplicates.
  • Added SetArgs and SetColor methods to TextComponent, and a Component field for accessing the text component.
  • Added a new CustomTableField element for creating small tables.
  • Added an IsExpanded field to CustomDropdown to indicate if the content is currently expanded.
  • Added a method to CustomToggleGroup to get the index of a CustomToggle.
  • Added a SetColor method to TimerDefaultView for setting text color.
  • Added a Clear method to CustomTableItemVisual.
  • Added an ArrangeBatchAsync method to the CustomTableView class for batched table population.
  • Added a **_delay** field to the GameObjectActive state for delayed command execution.
  • Added a new LocalScale change state to the RectTransformTransition state.
  • Added a RemoveStateObject method to the TransitionStates class for removing states.
  • Added an UpdateOnDisabled field to the View class, allowing it to update even when inactive in the scene.
  • Added an InitializedIfDisable field to the Visual class for initializing on scene load even if the object is inactive.
  • Added a new CursorExtensions class for tracking cursor state.
  • Added SteamGameVersion (for the Steam build version) and SteamId (for the Steam App ID) fields to GlobalConfig.
  • Added an EncryptUserData field to GlobalConfig to enable save file encryption (works only in builds).
  • Added 4 Steam languages to the game settings GameSettingsData: Spanish, French, Italian, German.
  • Added a SteamClouds field to the game settings GameSettingsData to enable/disable Steam Cloud saves.
  • Added a fast-forward method to CustomTimer (editor only).
  • Modified and improved file generation patterns (regeneration required, backup recommended).
  • UIScaler and Dispatcher have been moved to the DI container.
  • Added a WaitForSteamLaunch method to SteamManager. The game will not start until Steam is initialized.
  • Improved the StateMachine class, added a CurrentState field and an instant parameter to SetState methods for instant state changes.
  • The state machine in CustomTabsVisual has been reworked for easier management.
  • Made minor changes to the CustomToggle structure.
  • Changed UserData handling. In the editor, all data is now saved to a separate file with the Editor.json* postfix.
  • Added the ability to set a custom format for the timer in **TimerDefaultVisual.
  • GlobalVisual now automatically validates the canvas and adjusts it to the default screen size from game settings.
  • Added the option to disable cursor icon changes in CustomCursor.
  • Fixed freezes and optimized performance for TextComponent and the CustomEnumPopupDrawer dropdown.
  • Fixed the display of the ReadOnlyAttributeDrawer in the inspector when nested inside a list.
  • Fixed a bug where the game would pause with the P key while the console was active.
  • Fixed an issue in CustomUIGraphicComponent where a custom color would not be set (it kept resetting to the _colorTag value).
  • Fixed the RectTransformTransition state affecting objects that were inactive in the scene.
  • Fixed incorrect behavior of some states in the editor that could persist after exiting play mode.
  • Fixed an issue with SingletonMonoBehaviour and SingletonScriptableObject for engine version 6 and above.
