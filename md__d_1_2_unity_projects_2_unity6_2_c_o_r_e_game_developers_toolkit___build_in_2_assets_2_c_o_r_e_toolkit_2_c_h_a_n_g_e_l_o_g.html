Every change starts with the part of CORE it belongs to — {audio} here, a dot of the part's color in the Welcome window. Each part has a version of its own: major when a change breaks code or needs a migration, minor for a feature, patch for fixes.

1.3.93 — 2026-11-02

Full gamepad support comes in 1.3, stage by stage: input modes and device detection, UI navigation by layers, groups and elements, prompts and button icons, a virtual cursor, haptics, Steam Deck readability and local multiplayer — on top of the existing InputSystem, which keeps its API. This section grows with every stage.

Input

  • {input} InputGamepadSettings — the settings of the gamepad support: modes and device detection, navigation, virtual cursor, haptics, Steam Deck, button icons. CORE's defaults are Resources/CoreInputDefaults; the game's own Resources/CoreInputSettings, created in Tools/CORE/Settings → Input, wins. Action references left empty fall back to CORE's UI and VirtualCursor maps by name.
  • {input} InputHost — bound in ProjectInstaller, builds the gamepad services in a fixed order once the game initializes and ticks them on unscaled time through GlobalUpdater: IsInitialized, Initialized, Disposing, WhenInitialized, Settings, Input. The services of the later stages are its properties.
  • {input} InputSystem.ResolveAction — an InputActionReference, an action of the asset on disk or a (map, action) pair becomes the action of the runtime copy with the same id, so rebinds and device detection see one action; the asset on disk is never served.
  • {input} InputMode, GamepadFamily, EventSystemPolicy and the navigation enums UIGroupNavigationMode, UIGroupSwitchPolicy, UINavigationDirection, UIGridScoringMode, UIInputPressTrigger.
  • {input} Input modes and device detection: InputHost.Mode (InputModeService — CurrentMode, SetInputMode, InputModeChanged) and InputHost.Devices (InputDeviceService — ActiveDevice, CurrentGamepadFamily, Classify, ActiveDeviceChanged, GamepadFamilyChanged), with the host's own CurrentMode, CurrentDevice, CurrentGamepadFamily and events. The mode follows the last meaningfully used device: every triggered action is weighed by its control's magnitude against the thresholds, and the current gamepad, keyboard and mouse are polled every frame, so a device counts even with no map of it enabled. A mouse warp, a non-native mouse (the virtual cursor) and the mouse inside InputHost.SuppressMouseDeviceUsed never count. A removed active device falls back to the current gamepad, any gamepad, the keyboard, the native mouse — in that order.
  • {input} InputHost.CursorControl (CursorControlService): the hardware cursor is hidden and locked in the Gamepad mode (lock mode and every-frame enforcement from InputCursorSettings) and the previous state comes back in Keyboard&Mouse and on dispose; IsCursorBlocked. CustomCursor keeps swapping the cursor image as before.
  • {input} InputHost.Icons (InputIconService): TryResolve(action | reference, family, out InputIconContent) — the icon and LocKey label of an action for the gamepad family from InputGamepadSettings.ActionIcons (the Generic entry is the fallback); GetBindingDisplay(action, bindingIndex) and GetControlDisplay(controlPath) — what a binding shows on the controls screen, rebinds included: the human-readable control name (Latin whatever the layout; a composite joins its parts, W/S/A/D), the ControlIcons entry's icon and label when there is one, else CORE's key sprite of the path's KeyCode in InputGamepadSettings.KeyIconSize. InputLabel.Resolve(key) turns a label key into text: a key in the tables gives its translation, any other is shown as typed.
  • {input} UIInputStandaloneIcon (CORE/Input/UI Input Standalone Icon): an Image that shows the icon of an action for the active family and follows every family change; Bind(action | reference | map, action), ClearBinding, Refresh. For HUD prompts and tutorials, independent of the navigation and the input mode.
  • {input} InputSceneComponent — the base of the gamepad scene components: the InputHost comes through DI (the creating container, else DiContainerRef.Container in Awake, else a later Container.Inject), OnAttach / OnDetach are balanced whatever the order of injection and enabling.
  • {input} InputHost.UI (UIInputService): the EventSystem and its InputSystemUIInputModule on behalf of the navigation. In the Gamepad mode the module's move/submit/cancel are taken away (CORE's navigation is their one owner) and given back in Keyboard&Mouse and on dispose; EventSystemPolicy.UseExisting (the default — the ProjectContext has one) never adds or removes modules, CreateIfMissing creates CoreInputEventSystem when the scene has none; a destroyed EventSystem is followed by EventSystem.current, a working one is never replaced. SetSelected, ClearSelected, RestoreSelection (the focus target, else the last selection) — restored on entering Gamepad with RestoreFocusForGamepad, cleared on Keyboard&Mouse with ClearFocusForKeyboardMouse.
  • {input} Navigation contexts — the base of local multiplayer that lives in the core: InputHost.Contexts (UINavigationContextHost) holds a UINavigationContext per player (Primary, ForPlayer(i), Available, AvailabilityChanged; a context has IsAvailable, Mode, GamepadFamily, GamepadInputGate, AccentColor, ResolveAction, ModeChanged, GamepadFamilyChanged). UINavigationScope (CORE/Input/UI Navigation Scope) on a panel's root routes everything below it to a player (PlayerIndex, SetPlayerIndex, SetContext); Contexts.Resolve(component) answers the primary without walking the hierarchy while no scope is alive, Resolve(component, ref UINavigationScopeCache) caches by Version, InvalidateCaches after reparenting a subtree; IUINavigationContextListener components are told when the routing may have changed (a panel switched off as a whole does not wake them).
  • {input} InputHost.GamepadInputGate (GamepadInputActivationGate): after entering the Gamepad mode the UI input is held back until the sticks, the D-pad and the navigate action are neutral (SuppressInputOnGamepadEnter; one repeat delay without a navigate action) — the stick that opened a menu does not navigate it; IsInputAllowed, ArmSuppression.
  • {input} UI navigation by gamepad — the components (CORE/Input/…): UIInputLayer (a screen or panel: a stack entry of its player's navigation; AutoActivate enters the stack when enabled in the Gamepad mode, AllowEmptyGroup, RememberLastFocus, DefaultGroup, Push / Remove / Rebuild / MarkDirty, BackRequested — the layer never closes a window), UIInputGroup (a list, grid or ring of elements: NavigationMode, GridScoring, SwitchPolicy with Left/Right/Up/DownGroup links, DefaultElement, RememberLastElement, AllowExternalNavigation, ActivationAction / ExitAction, Activated / Deactivated), UIInputElement on a Selectable (UIInputElementBase to derive from: Priority, IsNavigationEnabled, AllowInputSubmit, Selected / Deselected, IsFocused, SubmitFromCode; availability = the Selectable interactable, the CanvasGroup chain, IUIInputElementAvailability components next to it, the game's IUIInputRestrictions). Elements are ordered by Priority then by place in the hierarchy; the explicit Unity navigation of the Selectables mirrors CORE's order (UINavigationMap).
  • {input} InputHost.Navigation (IUINavigationService, every player's is UINavigationContext.Navigation): the layer stack — the top is decided by canvas sorting order and hierarchy, not push order — ActiveLayer / ActiveGroup / ActiveElement, Move, Submit, Cancel (a Back that changed the stack is consumed for the frame: LastBackConsumedFrame), Lock, ValidateFocus, MarkDirty (rebuilds are deferred and merged, flushed in LateUpdate before the focus is validated), PresentFocus; events ActiveLayerChanged, ActiveGroupChanged, ActiveElementChanged, NavigationMapRebuilt, FocusLost, FocusRestored, BackRequested, LockChanged. Lives in the Gamepad mode only: the layers are cleared in Keyboard&Mouse and the enabled auto-activating ones come back on the way in. The primary's focus is the EventSystem selection and is put back on it every LateUpdate; a player's focus goes through the select handlers.
  • {input} The navigation's input: InputHost.NavigationInput (UINavigationInputProvider — the navigate, submit and cancel actions of InputNavigationSettings, else CORE's UI map: deadzone, hysteresis on diagonals, key repeat by RepeatDelay / RepeatRate, SuppressHeldDirection) and InputHost.GroupSelectionInput (UIGroupSelectionInputProvider — a layer that allows an empty focus is entered by a group's ActivationAction and left by its ExitAction). Both run in the Gamepad mode only, behind the activation gate; the map of the actions is enabled through CORE's providers (InputSystem.RegisterProvider(mapName)), so a restricted group still silences it.
  • {input} The navigation is locked by the system while the console is open or the UI group is restricted (a save), on top of the game's Lock; InputHost.SetRestrictions(IUIInputRestrictions) vetoes elements (call ValidateFocus after a change); InputHost.BackRequested, RequestBack(); UIInputLayerBackHidesVisual — the VVM glue: Back on the layer hides the Visual it sits in.
  • {input} UIInputButton (CORE/Input/UI Input Button): a shortcut — a Selectable pressed by a gamepad action outside the focus: on press, on release (PressTrigger) or after a hold (PressDuration, HoldProgressFill); submits the Selectable (InvokeSelectableSubmit), Pressed; live only while the binding is active (SetBindingActive), on one of the AttachedLayers, with one of the AttachedElements focused, or with no element focused (HideWhenAnyElementFocused); hides its VisibilityRoot while not live (HideWhenBindingInactive) or while the Selectable is not interactable (HideWhenSelectableDisabled). Pressed by InputHost.UIBindings (UIInputBindingService, one per player): Gamepad mode only, behind the gate, and never by the press a navigation Back just consumed — a close button on the east button does not fire together with Back.
  • {input} Hints (CORE/Input/UI Input Layer Hint / Group Hint / Element Hint, UIInputHintBase to derive from): prompts that appear with the focus — the active layer's, the active element's, the active group's; a group hint with the group's ActivationAction is the prompt to enter the group while the layer has no active group, with RequiredElements / RequiredGroups / RequiredTransformActiveChildren as conditions. A hint switches its Targets (else itself), refreshes its Icons and tints TintGraphics with the player's accent color. Driven by InputHost.Hints (UIInputHintService): SetVisible / AreVisible / VisibilityChanged (hidden hints also mean no prompts), a LateUpdate drift check for prompts whose group became available without an event.
  • {input} UIInputIcon (CORE/Input/UI Input Icon): the icon and label of an action inside a hint or next to a UIInputButton — the action of the button, else InputAction (SetInputAction for the hints); shown for the active family while the player's prompts are live, the button may be shown and the hint allows icons; Contents switched with it, LabelText from CustomLabel or the action's label, refreshed on every language change.
  • {input} Element variants (CORE/Input/…, CORE.Shared.Inputs.Widgets): UIInputEmptyElement (no Selectable — a card, a tooltip anchor; Submit toggles Submitted / SubmitCanceled, losing the focus cancels), UIInputSliderElement (two actions move the slider while it holds the focus: a step on the press, a steady move while held, a whole-number slider keeps the remainder), UIInputDualButtonElement (two shortcut buttons whose bindings are live only while the row is focused — "Equip" and "Drop" on every inventory row), UIInputNestedLayerElement (Submit enters the nested TargetLayer, Back leaves it and the focus comes back; an empty layer is retried next frame, an emptied one is left by itself; Entered / Exited; UIInputNestedLayerBackRequester for a layer pushed from code, UIInputNestedLayerElementHint hides its icons while the layer cannot be entered).
  • {input} Widgets: UIInputTabController (tabs by two shortcut buttons or by clicking; the active tab's content group is shown and focused, mouse-only tabs (HideOnGamepad) disappear on the gamepad, state applied after the frame's LateUpdates), UIInputCycleController + UIInputCycleItem (a selection cycled by the shoulders through filter tabs or categories, with wrap, optional submit on every transition, the item hint UIInputCycleItemHint on the selected one), UIInputScrollController (the right stick scrolls a ScrollRect while the target layer is active; UIInputScrollHint while there is something to scroll), UIInputScrollIntoView (scrolls the focused element into the viewport, instant or animated).
  • {input} The selection frame: the shader CORE/UI/InputFrame (a solid rounded line of _Thickness pixels, anti-aliased, geometry from the rect so any sprite or Image type works and the line keeps its width), UIInputFrameRectSize (feeds the shader from the Image), UIFrameTargetFitter (wraps a target RectTransform with a padding, across hierarchy branches).
  • {input} InputHost.VirtualCursor (VirtualCursorService): the stick-driven cursor — a real virtual Mouse device VirtualCursorMouse the UGUI input module follows like any mouse, Mouse.current while the cursor is active (so InputPointer and CustomCursor read it as is), plus simulated pointer events for a scene without the module (IncludeUIMouseClick). Enable / Disable / SetEnabled (requested; active only in VirtualCursorSettings.AllowedInputModes, IsEnabled, EnabledChanged), Show / Hide (IsVisible, VisibilityChanged), Position / SetPosition / MouseInput, Pin(provider) / Unpin (follows a moving target, re-read in LateUpdate), SetSpeedShaper, SetSprite / SetSpriteById / ResetSprite, SimulateMouseClick, IsPressed. The submit press that activated the cursor does not click; going away warps the hardware mouse to the cursor under SuppressMouseDeviceUsed, and the virtual device is removed after the input update, never inside a callback.
  • {input} VirtualCursorMagnet (CORE/Input/Virtual Cursor Magnet): a UI element the cursor is pulled towards within VirtualCursorMagnetSettings.Radius (RadiusOverride per magnet), released by the stick past ReleaseThreshold; VirtualCursorView — the cursor's image on an Overlay canvas, built in code or from VirtualCursorSettings.CanvasPrefab, with SetSprite / SetVisible / SetColor.
  • {input} InputHost.Haptics (HapticsService): gamepad vibration — Play(low, high, duration) for a pulse on unscaled time, SetMotorSpeeds(low, high) for a rumble, Stop, IsVibrating; SetEnabled / IsEnabled and MasterIntensity (0..1, applied to a running vibration; SettingsChanged) start from InputHapticsSettings. The vibration follows the active device: to another gamepad it moves, on a keyboard or on leaving the Gamepad mode it stops (StopOnInputModeChange); without an active gamepad the current one vibrates.
  • {input} The player's vibration choice: ControlSettingsData.HapticsEnabled / HapticsIntensity in Settings.Controls, read by the service on every Settings.Apply and written by its setters when InputHapticsSettings.PersistSettings is on; HapticsService.SaveSettings() writes them and saves the settings to disk (false with a warning while persistence is off).
  • {input} Rebinding, extended: InputSystem.StartRebinding(action, bindingIndex, onComplete, onCancel) for any action (resolved to the runtime copy, so the asset on disk is never dirtied) — one rebind at a time, the action disabled while it listens, RebindStarted / RebindCompleted / RebindCanceled, IsRebindActive, CancelRebinding; only bindings of the keyboard-and-mouse group are rebindable (KeyboardMouseBindingGroup, resolved from the asset's control schemes by InputBindingGroups — "PC" or "KBM" work too; IsBindingRebindable, GetRebindableBindingIndexes), gamepads, the pointer axes and the left and right mouse buttons never complete one (ExcludedRebindControls); several cancel controls through SetCancelControlPaths (Escape by default), and a cancel by a gamepad button is not a Back of the navigation nor a shortcut press in that frame.
